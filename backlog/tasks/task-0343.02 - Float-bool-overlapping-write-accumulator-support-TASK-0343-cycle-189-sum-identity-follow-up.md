## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0343 cycle 189 returns EmitError::ContractGap for float / bool scalar accumulators on the overlapping-write fan-in path (backend-common/src/multi_worker_walker/wait.rs::accumulate_op_for_scalar). Two distinct sub-problems:

1. Float (f32/f64): sum order is not associative-stable. Per PRD §10.1 bit-identity invariant, the host-side fan-in cannot use unordered + . Possible approaches: (a) require deterministic Kahan-summation kernels declared by the user; (b) reject the schedule at link time with a typed error; (c) sort by worker id then accumulate (cross-backend stable but slow). Decide and document.

2. Bool: no canonical sum identity. The user-level intent (OR fan-in vs AND fan-in vs XOR fan-in) must be declared explicitly. Subsumed by the algebraic-identity-from-kernel-attribute follow-up (sibling sub-task).

Cross-references:
- TASK-0343 (parent): the cycle-189 carve-out landing.
- PRD §10.1: bit-determinism invariant.
