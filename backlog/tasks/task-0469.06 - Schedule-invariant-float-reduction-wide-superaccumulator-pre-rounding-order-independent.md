## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Numerics breadth. TASK-0453.03 landed the FIXED-ORDER route (combine=fsum, worker-id-sorted fold): reproducible across backends for a GIVEN schedule, but a different worker count folds differently and can yield different bits — same bytes across backends, not across schedules. The stronger order-INDEPENDENT route is explicitly still future work (0453.03 notes; thesis ch11 sec:fw-float): a reduction that computes a fixed result regardless of summation order and worker count, via a wide fixed-point superaccumulator (an integer accumulator wide enough to absorb every addend without rounding) or by pre-rounding addends to a common granularity (Demmel-Nguyen style). This opens the numerics audience that currently bounces off the integer-centric story and lifts the not-across-schedules asterisk on fsum. CRITICAL lockstep constraint (same as fsum): the frozen reference oracle must adopt the identical scheme, so reduction lowering + kernel contract + reference move together; the result is the scheme own value (the exact sum for a superaccumulator), not necessarily the naive single-pass IEEE sum. Keep it opt-in; plain float sum stays rejected.
