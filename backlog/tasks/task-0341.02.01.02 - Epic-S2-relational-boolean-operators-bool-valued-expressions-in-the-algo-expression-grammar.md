## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
=== Forward-carried scoping from cycle-256 (orchestrator code-read, pre-implementation) ===
CONSUMER FACT (corrects the design-review framing): the dataflow RHS parser uses the FULL expr_parser(), NOT the doc-grammar restricted RValue ::= CallExpr | LValue (parser.rs stmt_parser dataflow arm: lvalue <-- expr_parser() ;). So relational operators added to expr_parser are immediately reachable in (a) any dataflow RHS, (b) index positions, (c) for-loop bound positions. (a) is the standalone consumer; (b)/(c) are semantically invalid (bool in int position) and MUST be rejected with a TYPED error, not silently accepted (panic-not-diagnostic + the bool-in-int type rule).
DESIGN DECISIONS to make in this slice:
1. AST shape: prefer a DEDICATED Expr::Compare(CmpOp, lhs, rhs) node over extending the arithmetic BinOp enum (ast.rs:173 BinOp{Add,Sub,Mul,Div,Mod} is integer-arith; bool result is a distinct type/precedence — mixing risks treating a comparison as an int operand). Precedence: relational is a NEW level BELOW additive (RelExpr ::= AddExpr ((op) AddExpr)?), non-associative single comparison (no a<b<c).
2. Result TYPE is bool. Where-allowed rule: accept only where a bool is expected. Today that is ONLY a bool-typed dataflow RHS (data flag : bool; flag <-- a<=b;) and (future) the S1 until-condition. REJECT in index/bound position with a typed error.
3. BOOL-DATA CODEGEN SCOPE QUESTION: a fully-e2e standalone test (bool-typed dataflow) drags in bool-data-buffer codegen (Vec<bool>? input.bin layout?) which may be untested. If bool-data codegen is out of scope, land S2 as parser+AST+IR+lower with a PARSE+AST+lower unit test (positive) + a typed-rejection test in index position (negative), and DEFER the e2e bool-data consumer to S1 (where until-condition is the real consumer). Decide + document which.
4. ir.rs IrExpr needs a matching Compare node; lower.rs maps it; backend-common render maps to Rust a<=b. Determinism: relational on ints is exact/order-free (no concern).
