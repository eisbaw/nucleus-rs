## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
First sub-slice of TASK-0438. Thread a new per-transfer-edge transport-mode HINT through the schedule DSL end-to-end, WITHOUT any backend codegen divergence yet (that is TASK-0438.02).

Grammar: add `mode=pio` | `mode=dma` as a new `TransferOption` choice arm, modelled exactly on the existing `notify=event|poll` arm. Example usage: `transfer mic_in : async, mode=dma;` / `transfer ctl : sync, mode=pio;`.

Threading path (exact current pointers from parent pre-brief):
1. AST: nucleus/nucleus-compiler/src/sched/ast.rs:307 — add `TransferOption::Transport(TransportMode)` + `pub enum TransportMode { Pio, Dma }` (mirror NotifyKind shape).
2. Parser: nucleus/nucleus-compiler/src/sched/parser.rs:607 `transfer_option()` — add a `mode=` arm to the choice, modelled on `notify`.
3. Lower: nucleus/nucleus-compiler/src/sched/lower.rs:1119-1206 — handle the new variant AND add the dup-check arm (DuplicateTransferOption). A second `mode=` must be a typed SchedLowerError, NOT silently dropped.
4. IR: nucleus/nucleus-compiler/src/sched/ir.rs:283-299 — add `ResolvedTransferOption::Transport(TransportMode)`.
5. Capabilities: nucleus/nucleus-compiler/src/capabilities.rs:347-394 — add the match arm; no silent `_ =>` catch-all.
6. TransferPolicy: nucleus/nucleus-compiler/src/passes/transfer_inject/ordering.rs:776-786 `policy_from_directive` — add a `transport: TransportMode` field (default Pio), populated from the resolved option. TASK-0438.02 will read this.

CRITICAL anti-silent-drop (memory feedback-option-none-skip-arm-silent-drop): the hint must be CARRIED into TransferPolicy as a typed field, not parsed-and-ignored. Identical PIO render for both modes is acceptable ONLY because divergence is deferred to TASK-0438.02 and referenced in a code comment at the policy site.

Regression safety: 02-split-add + 14-hearing-aid use no `mode=` -> default Pio -> byte-identical emit. renode-multimcu-gate (02 + ex14) must stay BYTE-EXACT.
