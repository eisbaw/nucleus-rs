## Description

Follow-up to TASK-0048.01 (which proved the EMISSION pipeline with zero-filled stub inputs => deterministic ASCII line 'NUC-EX1 len=1024 checksum=0'). This task makes the generated STM32H7 firmware compute on REAL input data and stream the actual result for a binary diff vs reference.bin. Two pieces: (1) a real input path — the load_input/load_input_b effectful hooks currently no-op (alloc_in_region returns null, dma_wait no-ops), so a/b stay zero; needs either a Renode-injected input region (sysbus WriteBytes / a memory file backend) or embedding input.bin bytes into the firmware. (2) stream the raw output bytes (or a strengthened framing) over USART1 and binary-diff the captured bytes against reference.bin (replace the grep-q ASCII assertion with a byte-exact diff), per PRD §10.3 point 3. Note the carried Renode caveat: STM32F7_USART hardwires TXE=true so raw streaming is fine but back-pressure is unvalidated.

## Cycle 239 implementation (real injected input + byte-exact reference.bin diff) — commit f297c11

### Mechanism choice: (B) Renode-injected region, NOT (A) firmware-baked static
DE-RISKED FIRST with a throwaway STM32H7 firmware (mandatory, mirroring cycle-237). Two proofs in-sandbox before any codegen:
1. firmware reads word0 from axiSram @ 0x24000000 after .resc did 'sysbus LoadBinary @input.bin 0x24000000' -> captured 'INPUT0=7' == input.bin a[0] (Renode log showed 'Loading block of 2048 bytes length at 0x24000000' BEFORE the CPU started; load ordering correct).
2. full path: firmware read a[0..N]+b[0..N], computed c, streamed RAW 1024 bytes -> cmp -s identical to reference.bin. Both halves (input + raw-output capture) proven, then scratch deleted.
WHY (B) over (A): architecturally honest (input arrives from a memory region the platform models, closer to the real DMA-from-peripheral shim of parent AC#1); no fixture baked into flash; fully deterministic in-sandbox. The KEY enabler is axiSram @ 0x24000000 (512K): mapped in platforms/cpus/stm32h743.repl but NOT in our memory.x (which is only FLASH@0x08000000 + DTCM RAM@0x20000000), so the linker never places stack/.bss there -> the injected fixture cannot collide. (A) remains a viable fallback if a future target lacks an unmapped-but-modelled region.

### Gotchas / subtleties (for the next slice)
- Renode load ordering: 'sysbus LoadBinary @input.bin <addr>' in the .resc executes before RunFor, so the region is populated before the CPU boots. dma_wait can be a no-op (synchronous). A real async DMA shim (parent AC#1) would NOT have this luxury.
- The cursor assumes input.bin = loads concatenated in EventList order. Exact for ex1 (a then b). Single-load examples (ex5 load_image, ex9 load_input) trivially fit. Pinned as TASK-0048.06 for the ex5/ex9 generalisation — verify per example, do not assume.
- The 'region' arg of alloc_in_region is ignored (always region 0 / the single injected region). Multi-region placement (place_data in tcm_per_core) is M10-shim/M11.
- __src is reused as a binding name across the two loads (shadowing) — fine in Rust.
- endianness: input.bin/reference.bin are LE i32; the Cortex-M7 is LE; the firmware does a raw byte copy (no swap needed) and a raw byte stream out — LE preserved end-to-end. A BE target would need a swap.
- read_volatile on the byte loads in dma_push: prevents the compiler reordering/eliding the loads across the MMIO writes in usart1_putc.

### Rejected approaches
- Adding a new trait method (e.g. fill_from_input): rejected to keep the NucleusShim surface STABLE (the parent-note item 1 says the M10 shim relies on the alloc_in_region+dma_wait load hooks). Reused alloc_in_region's existing returned-pointer contract instead.
- Streaming a framed payload (length prefix + checksum) then stripping before cmp: rejected — raw bytes are simpler and Renode's USART file backend captures them faithfully (proven in de-risk); the byte-count guard + cmp is a sufficient and honest assertion.
