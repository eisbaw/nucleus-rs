### Reactor + Chan design (emitted runtime)

The emitted per-worker binary owns ONE non-generic mio Reactor:
- Holds mio::Poll + mio::Events + per-peer TcpStream (DATA channel).
- Outbound queues: BTreeMap<(SeqTag, peer), VecDeque<Vec<u8>>>. Capacity = sidecar.transfer_buffer_for_seq[seq].
- Inbound queues:  BTreeMap<SeqTag, VecDeque<Vec<u8>>>.
- Partial-frame state per peer (header buffer + payload buffer + bytes_read).
- Per-peer pending-write byte cursor for partial writes when socket fills.
- Token allocation: mio::Token(peer_index * 2) for read, Token(peer_index * 2 + 1) for nothing (we register interest on both edges via interest set, no separate write token).

The chan_<rid> abstraction at the user level is a typed wrapper:
- struct Chan<T> { reactor: Rc<RefCell<Reactor>>, seq: u64, peer: usize, cap: usize, encode: fn(&T) -> Vec<u8>, decode: fn(&[u8]) -> T }.
- chan.push(v):   self.reactor.borrow_mut().push(self.seq, self.peer, (self.encode)(&v), self.cap)
- chan.wait() -> T: let buf = self.reactor.borrow_mut().wait(self.seq); (self.decode)(&buf)

CTRL channel (barriers) stays SYNCHRONOUS using existing wire::barrier_cross — same shape as mp-tcp-bufsync. Two separate TCP sockets per (host,worker): DATA (mio-managed, non-blocking) + CTRL (std blocking, only for barriers).

### File layout to emit per worker binary
- mod wire;            (verbatim WIRE_RUNTIME_SRC)
- mod kernels;
- File-scope Reactor struct + impl.
- File-scope Chan<T> generic + impl.
- main(): connect (host=server, non-host=client), build reactor with peer sockets registered, build chan_<rid> instances with sidecar-derived caps + per-type encode/decode fn pointers, then the shared walker output.

### Handshake (same as mp-tcp-bufsync post-TASK-0176)
- DATA + CTRL sockets per (host,worker) pair — 2 accept()/2 connect_retry().
- Host binds 127.0.0.1:0 ITSELF per non-host worker, publishes port atomically (tmp + rename) to NUC_RENDEZVOUS_DIR/<wname>.port.
- Non-host polls for the port file (600 x 10ms = 6s) then connects DATA then CTRL.
- DO NOT reintroduce __nuc_pick_port.
- Hand-off DATA socket to mio (set_nonblocking + register); keep CTRL std-blocking for barriers.

### Walker integration
- WalkerCtx { rendezvous_prefix: "chan" } — emits chan_<rid>.push(name.clone()) / chan_<rid>.wait().
- New backend-private struct Plan<'a>: per_worker, names, sidecar, used_workers, host_worker, ring_ids: BTreeMap<(DataId,SeqTag), usize>, ring_caps: BTreeMap<(DataId,SeqTag), u64> (from transfer_buffer_for_seq), pair_tiles, barrier_participants. Mirrors pthreads-async Plan, but emits per-(src,dst) PEER-INDEXED outbound queues (the additional peer dim mp-tcp needs).

### Honest limitations + forward-carried lessons

1. **TASK-0175 (worker-to-worker mesh) is the only remaining blocker on AC#2/AC#4.** mp-tcp-event's star topology lifts straight from mp-tcp-bufsync; until a worker-to-worker channel layer lands, both backends share the same w↔w gap. AC#2/AC#4 will close as part of TASK-0175 closure, not as a Stage-3 follow-up. The 09/pipelined cell carries the same SHA256 oracle pthreads-async runs today.

2. **mio reactor design**: the reactor lives on the single worker-process thread (single-threaded RefCell<Reactor>; one Chan<T>::push or .wait at a time). Push enqueues then OPPORTUNISTICALLY drains non-blockingly — this is load-bearing: without it, a Push followed by a long compute-or-barrier stretch would leave the producer's data invisible to the consumer (which is parked on Chan::wait polling). The opportunistic drain after enqueue is a steady-state guarantee: 'every push observed by the producer either reaches the kernel send buffer, or the kernel refused (WouldBlock) and the next push/wait pumps it'. Filed: tighten this contract in runtime_src.rs's Reactor::push docstring (DONE in cycle 79).

3. **Barrier shim approach**: the shared walker emits {prefix}bar_<bid>.wait(). To keep using the walker UNCHANGED, mp-tcp-event emits a per-barrier struct shim that wraps Rc<RefCell<std::net::TcpStream>> handles and calls wire::barrier_cross on them. CTRL streams MUST be Rc<RefCell<_>>-wrapped from the start (each barrier captures clones; can't use &mut). Lesson for any future tcp-async backend that wants the shared walker: pre-wrap CTRL streams in Rc<RefCell<_>> in the handshake emit.

4. **Frame demultiplex by seq, NOT by source peer**: the design relies on globally-unique SeqTag (TASK-0233 contract). Two Pushes from different peers cannot collide on the same seq because (DataId, SeqTag) is unique per Push/Wait pair. The reactor's inbound queue is keyed on seq alone; this simplifies the demultiplex and means a Chan<T>::wait() doesn't need to know the source peer.

5. **fmt baseline drift**: cargo fmt --all in this cycle wanted to reformat 57+ unrelated workspace files. I reverted those and applied rustfmt only to my own files. Future cleanup should be its own task; flagged for TASK-0244 follow-up or a dedicated fmt sweep.

6. **No backend-common::project_skeleton::multi_binary lift**: the task description suggested optionally lifting the multi-process Cargo.toml / run.sh / rendezvous emit helpers into backend-common. I deferred — would have touched >500 LoC across mp-tcp-bufsync + new module + tests, and the risk profile was high (could perturb the byte-identical mp-tcp-bufsync emit). Filed a follow-up note in this cycle's tracker entry; a clean cycle dedicated to the lift can land it post-Stage-3-stability.
