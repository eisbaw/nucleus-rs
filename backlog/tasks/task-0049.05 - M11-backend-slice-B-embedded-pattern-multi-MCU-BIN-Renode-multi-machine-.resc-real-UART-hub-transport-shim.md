## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
=== Forward-carried from TASK-0049.04 (M11 backend slice A, LIB path DONE) ===

The STRUCTURAL multi-worker emit landed on the LIB path. The BIN slice (this task) inherits these shapes — do NOT rediscover them:

1. TRANSPORT LOWERING SHAPE (already implemented in render_event for the lib; the bin shares lower_kernels_and_run/render_run_body, so the SAME run-body lowering applies once the bin guard lifts):
   - Event::Push { data, seq } -> shim.dma_push(seq, <data>.as_ptr() as *const u8, core::mem::size_of_val(&<data>))  [mirrors the save->dma_push template]
   - Event::Wait { data, seq } -> shim.dma_wait(seq)  [data received into a zero-init receive LOCAL]
   - Event::Sync { sync } -> shim.irq_barrier(sync as u32)
   chan = SeqTag.0 (Push/Wait pair shares seq), tag = SyncTag.0 (matches across participants). NO channel allocator — straight from the events.

2. RECEIVE-LOCAL MECHANISM: collect_referenced_data (lib.rs) now includes Push AND Wait data ids, so the run-body data decls declare a zero-init fixed [T;N] local for every Waited (and Pushed) symbol — the receiving worker has the symbol in scope WITHOUT loading it. For the BIN with a REAL Usart1-hub shim, dma_wait must actually poll RX + fill that local (the lib StubShim no-ops it, so zero-init is honest only for compile-only). The local is already declared; the bin shim just needs to populate it.

3. N-PROJECTS LAYOUT: the lib emits one project per used worker (single -> out_dir root; multi -> out_dir/<worker_name>/, name from NameTables.worker). The bin must mirror this (N firmware bins, one per MCU class), PLUS the .resc wiring them on a CreateUARTHub. BinEmitResult will need the same N-projects refactor emit() got (currently emit_bin returns a single BinEmitResult; multi-worker needs Vec).

4. THE BIN GUARD IS STILL UP (emit_bin lib.rs:~273): retained deliberately + pinned by bin_rejects_multi_worker_with_m11_forward_link. Lifting it is THIS task. Its message already forward-links here (TASK-0049.05).

5. BLOCKERS THE LIB SLICE HIT (and the bin will too) — see TASK-0049.06: the REAL example-14 embedded_multimcu schedule is rejected at check_schedule_compat (async+buffer=3+notify=event + heterogeneous worker classes + sram_shared/dsp_tcm regions) and its mix2/denoise have Vec<i32> bodies + fe_*/rf_* have no kernels.rs bodies. The bin slice will need (A) the synchronous-vs-async transport + worker-class capability decision and (B) no_std-clean per-frame kernels resolved BEFORE ex14 firmware can build. The UART-hub start-gating discipline (receiver RX-enabled before any sender TX — TASK-0049.01) is the cross-MCU analogue of the Sync barrier and MUST be emitted in the generated .resc.

6. EMPIRICAL-VERIFICATION LESSON: TASK-0192 proved lower/link/acfg admit ex14 via lower_for_test (IR passes only); that did NOT exercise the driver-level capability gate. The bin slice MUST test through the real driver path (or check_schedule_compat directly), not just lower_for_test, or it will repeat the slice-A surprise.
