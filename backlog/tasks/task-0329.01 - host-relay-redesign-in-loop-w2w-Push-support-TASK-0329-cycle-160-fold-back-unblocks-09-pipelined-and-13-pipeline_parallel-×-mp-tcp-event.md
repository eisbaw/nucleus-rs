## Background

TASK-0329 cycle 160 lifted the CTRL-arm host-excluding-barrier rejection in mp-tcp-bufsync / mp-tcp-event via the new compiler-level pass apply_host_mediation_inject. With that lift, the two in-tree TASK-0329 trigger cells (09-producer-consumer/pipelined × mp-tcp-event, 13-cnn-inference/pipeline_parallel × mp-tcp-event) now advance past the host-excluding-barrier ContractGap into TASK-0330's defensive guard against in-loop worker-to-worker Push events.

Both cells have worker-to-worker Pushes nested inside Loop bodies:
- 09/pipelined: producer pushes \`stream\` per iteration of \`for n in 0..16\` to consumer
- 13/pipeline_parallel: inter-stage transfers fire per-iteration on the pipelined image-batch loop

cycle-149's flat host-relay (\`Plan::render_relay_phase\` emits one batch outside any loop) cannot drain these — over-count and mis-order failure modes are why TASK-0330's defensive guard rejects them.

## Acceptance criteria

### AC#1: substantive host-relay redesign

Choose and implement one of (or composition of):
- (A) **Threaded host-relay**: spawn a thread in host main that polls the reactor for inbound w2w frames and forwards them concurrently with host's own work. CTRL barrier still works (separate stream).
- (B) **Interleaved host-relay**: per-Push site emit. For each w2w Push event, host immediately runs \`relay_one(seq, dst_peer, cap)\` when its inbound[seq] arrives. Requires re-modeling host's event list to include relay events.
- (C) **Nested-loop relay splice**: detect schedule shape; if w2w Pushes occur inside a Loop, splice a per-iter relay block inside the corresponding host Loop body. Requires structural matching of the source Loop in host's event list (handled today by petri_to_events via Event::Loop preservation).

Coverage requirements: 09-producer-consumer/pipelined × mp-tcp-event AND 13-cnn-inference/pipeline_parallel × mp-tcp-event must emit + run + verify bit-identical against the pthreads-async oracle.

### AC#2: TASK-0330's defensive guard becomes contingent

Once AC#1 lands, the TASK-0330 defensive guard either:
- Stays in place as a fall-back for shapes the redesign STILL doesn't handle (document precisely which).
- Or is removed if the redesign covers every in-loop w2w Push shape (sibling guard in mp-tcp-bufsync handled symmetrically per paired-lift discipline).

### AC#3: e2e cell promotions

Both 09-producer-consumer/pipelined × mp-tcp-event and 13-cnn-inference/pipeline_parallel × mp-tcp-event promote from [[skip]] to [[required]], bit-identical against reference.bin.
