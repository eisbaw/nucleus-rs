## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Architect P3 on TASK-0044.03.02.01 (silent-sibling sweep continuation): TWO MORE backend-common shared modules carry the identical over-exposure pattern that .01 fixed in event_plan/tcp_plan. (1) multi_worker_walker/mod.rs declares pub mod block_tag|collect|ctx|event_walker|wait; (2) render/mod.rs declares pub mod ctx|error|expr|fire|reuse|types. In BOTH, external consumers reach items only through the mod-level pub use re-exports (tests use backend_common::multi_worker_walker::<fn> / backend_common::render::<fn>, never ::collect::<fn> / ::fire::<fn> direct paths); the inner pub mod submodules have NO external direct-path use-import. So they could be pub(crate) mod (matching .01).

CRITICAL CAVEAT (architect): unlike event_plan/tcp_plan (which had NO external doc-links), many crates carry intra-doc-link references like [backend_common::render::fire::render_fire_arg] in prose. Narrowing render::fire (etc.) to pub(crate) would turn those cross-crate doc-links into BROKEN links -> a rustdoc warning that becomes an error if doc builds run under -D warnings. So this task MUST run cargo doc (not just cargo build/clippy) to confirm before narrowing, and either (a) re-point/relax the doc-links, or (b) leave the doc-linked submodules pub while narrowing the rest. Distinct from .01 precisely because of this doc-link surface. Fold into the TASK-0340.04 visibility-tightening thread. Compiler+rustdoc are the oracle; e2e must stay bit-identical 308/246/0/62/0 (codegen-inert).
