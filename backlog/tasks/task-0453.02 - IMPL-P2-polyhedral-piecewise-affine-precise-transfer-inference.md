(1) Producer/Push side has NO tile-based slicing. event_walker.rs:469-471 emits `{slot}.push({name}.clone())` UNCONDITIONALLY — the WHOLE array on every cross-worker edge. (2) Partition tiles are consumed ONLY by the receiver-side paste in render_wait_assign / wait_slice (multi_worker_walker/wait.rs): the worker pastes its band into a full-shaped local buffer via copy_from_slice using GLOBAL indices (e.g. a[0..128].copy_from_slice(&_tmp[0..128])). The non-prefix b[k][j] case keeps WHOLE b (let b = ...wait()).

(3) The receiver ALREADY supports the non-prefix shape (WaitSlice::Rows = full leading axis + banded inner), so the wait_slice convention is not the true blocker; the compute_partition_bounds_with_dim_prefix non-prefix DROP (partition.rs:605-617) is conservative for receiver correctness, not bandwidth.

CONSEQUENCE: a tile-precision-only change (make b[k][j] band-paste) would NOT reduce communication -> a RELABEL (forbidden). Genuinely reducing wire transfer requires re-architecting the Push/send+receive protocol across ALL 7 backends to transmit band-shaped payloads (slice source by producer tile + receiver pastes band-shaped recv), which (a) is large + cross-cutting, (b) carries the all-zero/wrong-bytes axis-mapping correctness risk, (c) may change message sizes feeding the soundness-gate boundedness marking. NOT a precision-only tweak; needs its own scoped project, not a single ping-pong cycle.

THESIS-ACCURACY SPILLOVER (for .12): ch10:188-201 says affine->"each worker receives a precise slice" vs non-affine->"broadcasts the whole array ... move far more data than necessary". At the WIRE level whole arrays are sent in BOTH cases; the inferred precise region is used for receiver-side gather correctness/footprint, NOT transfer volume. Honest statement: the compiler INFERS precise per-worker regions (used for correct paste) but the current backends TRANSMIT whole arrays and slice on receipt; exploiting inferred regions to cut transfer volume is unimplemented.
