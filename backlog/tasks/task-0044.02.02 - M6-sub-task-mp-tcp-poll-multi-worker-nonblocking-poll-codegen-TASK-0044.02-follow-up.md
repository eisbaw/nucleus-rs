## Goal

Land the multi-worker arm of mp-tcp-poll: nonblocking-read poll loop + wire-framed Push/Wait + Plan-shaped per-worker codegen. Same capability surface as mp-tcp-bufsync (sync + tcp + no buffer; supports_async=false, supports_buffer=false); every multi-worker schedule that mp-tcp-bufsync handles MUST emit bit-identical output under mp-tcp-poll.

This unblocks all multi-worker [[skip]] cells filed in TASK-0044.02 cycle 192:
- 02-split-add/split, 03-reduction/distributed, 06-separable-filter/distributed + distributed2, 07-matmul/distributed + distributed-2d, 08-histogram/distributed, 13-cnn-inference/batch_parallel

Each promotes to [[required]] once bit-identical is verified.

## Closest template

`nucleus/backends/mp-tcp-bufsync/src/{plan.rs, walkers.rs, encode.rs}` (~700 LoC total). The diff is the wait primitive:

- mp-tcp-bufsync calls `wire::read_msg_expect(stream, seq)` which blocks until a frame matching `seq` arrives.
- mp-tcp-poll must call a nonblocking-read loop with `std::thread::yield_now`. Set `TcpStream::set_nonblocking(true)` on every connect; wrap the read in `loop { match read { Ok(n) => …, Err(WouldBlock) => { std::thread::yield_now(); continue }, Err(e) => return Err(e) } }`. Bound the retry / add a deadline so a never-sending peer becomes a loud error, not a spin-deadlock.

The Plan structure (one TcpStream per (host, worker) ordered pair; rendezvous-file port handshake; barrier-over-TCP via SyncTag) is reused verbatim. Only the wait primitive in the emitted per-worker programs differs.
