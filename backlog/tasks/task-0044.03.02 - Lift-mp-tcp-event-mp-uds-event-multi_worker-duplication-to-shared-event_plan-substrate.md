## Context

TASK-0044.03.01 cycle 197 landed mp-uds-event multi-worker by COPYING mp-tcp-event's multi_worker/ subtree (~3000 LoC) with the TCP→UDS transport swap. The two backends now have:

- encode.rs: BYTE-IDENTICAL between mp-tcp-event and mp-uds-event.
- walkers.rs + relay.rs: differ ONLY in error-message branding (`mp-tcp-event` → `mp-uds-event`).
- worker_program.rs: bulk of the TCP→UDS call-site swaps (UnixListener vs TcpListener, UnixStream vs TcpStream, path-as-rendezvous vs port-in-file).

## Scope (distinct from TASK-0044.02.03)

This lift is DISTINCT from TASK-0044.02.03's bufsync+poll lift because the underlying Plan substrate is different:

- TASK-0044.02.03: bufsync/poll = blocking/nonblocking-poll FIFO Plan (~1700 LoC duplication).
- THIS TASK: event/uds = per-seq-demux mio reactor Plan (~3000 LoC duplication).

Two independent lift opportunities. Both follow the same shape: parameterise a small trait over the transport-specific details (Listener/Stream type, rendezvous mechanism, wire framing) and have both backends consume the shared crate.

## Suggested approach

1. New crate or backend-common module: `event_plan` (or `backend-common::event_plan`).
2. Trait `EventTransport`:
   - `type Listener`, `type Stream`
   - `fn listener_bind_call(...)` -> emit string (TcpListener::bind(addr) vs UnixListener::bind(path))
   - `fn stream_connect_call(...)` -> emit string
   - `fn mio_stream_type()` -> emit string ("mio::net::TcpStream" vs "mio::net::UnixStream")
   - `fn rendezvous_dir_strategy()` -> RendezvousDirStrategy enum (TASK-0044.03.01 cycle-197b architect P3.1 — the `/tmp`-mktemp swap surface lifts cleanly here)
3. mp-tcp-event: impl EventTransport for TcpTransport.
4. mp-uds-event: impl EventTransport for UdsTransport.

## Forward-carried from TASK-0044.02.03 (cycle 235, mp-tcp-bufsync+poll lift LANDED)

The sibling sync-TCP lift completed; lessons that bear on this event-backend lift:

1. **Trait shape that worked**: `WirePrimitives` with 3 consts (BACKEND_NAME for ContractGap diagnostics, FILE_HEADER_BACKEND + FILE_HEADER_TASK for the EMITTED `//! Generated by the X backend (TASK-Y,...)` header) + 5 fns (read_msg_expect_call/write_msg_call/barrier_cross_call build the call STRUCTURALLY via format!, sock_setup_extra(sock)->Option<String>, so_buf_comment()->&str, relay_banner(pad)->String). `Plan<'a, W>` carries `PhantomData<fn() -> W>`; ALL trait methods associated (no self) so no W value is threaded. Lives in backend-common/src/tcp_plan/.

2. **Canonical EmitError lives in backend-common ALREADY** — both backends `pub use backend_common::EmitError;`. In lifted code use `crate::EmitError` (= backend_common::EmitError) directly. `NameTables` is `nucleus_compiler::NameTables`. backend-common's only dep is nucleus-compiler — the lift adds NO new dep (wire::... strings are EMITTED text, not calls). Same will hold for mp-tcp-event/mp-uds-event.

3. **The #1 byte-drift risk is hand-transcription of \x20-escaped raw codegen strings** (the rendezvous/connect_retry blocks). My first build FAILED with an unclosed-delimiter because a sleep line + 2 closer braces had wrong \x20 counts. MITIGATION (do this proactively): after lifting any \x20-heavy raw string, run `awk '/x20/{n=gsub(/\\x20/,"");print n"|"$0}'` on BOTH the original git blob and the lifted file and `diff` the count|content sequences — must be 0 diff. Cheaper than chasing a compile error.

4. **Byte-identity verification technique (3 layers, all independent)**: (a) e2e 5-tuple unchanged; (b) the per-bin legal-swap canonicalisation oracle each backend already ships (event backends have their own equiv tests); (c) DIRECT `nucleus build --algo .. --sched .. --backend X --out DIR` for both backends + diff after reverting documented legal swaps — do NOT inspect post-`just e2e` scratch (deleted on success per memory project-e2e-harness-scratch-lifecycle).

5. **doc_lazy_continuation WILL fire** when you reword module-docs — a wrapped `//!` line beginning with `+`/`-`/`*` at column 5 is read as a Markdown list marker. I hit it on a '+ worker-program assembly' wrap; fixed by using commas/'and'. Re-run `just clippy` independently (it is -D warnings).

6. **ContractGap messages are NOT emitted code** — they are compile-time diagnostics, only weakly pinned by per-backend unit tests' substring asserts. A canonical shared message parameterised by W::BACKEND_NAME is fine as long as it retains every pinned substring (grep each backend's tests/*.rs for the asserts FIRST). mp-tcp-event/mp-uds-event likely have analogous host-excluding-barrier + wait-before-push message pins (TASK-0044.08/09/10/11 family) — audit those before collapsing.
