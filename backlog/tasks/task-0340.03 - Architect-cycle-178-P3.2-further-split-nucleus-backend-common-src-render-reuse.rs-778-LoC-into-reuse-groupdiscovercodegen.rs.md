## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Forward-carried from TASK-0340.10 (embedded-pattern mega-file split, cycle): TWO reusable lessons for any crate-root-file -> child-module split. (1) NO visibility widening needed for items the new child module uses: a child/descendant module can already see ancestor-private (`fn`) items, so do NOT reflexively bump to pub(crate)/pub(super) — the implementer did and the review caught it (kernel_name). Widen ONLY for items the PARENT must call back into (those genuinely need pub(crate)/pub(super)). (2) COMMENT-DOC-LIE TRAP (feedback-verbatim-copy-comment-doc-lie): moved code carries location-deixis ('see lib.rs X', intra-doc links [X], 'above/below') that becomes a LIE the instant X moves in the same commit. Pre-commit: grep the moved files for bare 'lib.rs'/'<oldfile>.rs'/[`fn`] links + above/below deixis and re-point each. Low-churn split trick: re-export moved items at the crate root (use child::*;) so tests.rs + sibling references resolve UNCHANGED (embedded-pattern tests.rs only used public emit/emit_bin, so it needed zero edits).
