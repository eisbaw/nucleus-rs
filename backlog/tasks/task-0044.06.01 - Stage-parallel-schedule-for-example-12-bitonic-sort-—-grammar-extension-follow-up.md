TASK-0044.06 cycle 200 honest-scope follow-up. The naive schedule for example 12 (bitonic sort) ships with a single fire site (`output <-- bitonic_sort(input)`) — the entire log2(N) outer × variable inner stage compare-exchange network lives in one pure Rust kernel because v2's no-conditionals + single-assignment-per-data-symbol + const-loop-bound rules forbid the natural stage-decomposed encoding (same fundamental limit as TASK-0179 1D in-array prefix scan and TASK-0044.05.01 2D wavefront).

Consequently the algorithm has NO decomposition axis the schedule sublanguage can attach a `partition=` or `pipeline=` directive to — only the naive schedule is shippable today.

The stage-parallel schedule (N/2 compare-exchange comparators concurrently within a stage; barrier between stages; total log2(N) outer × inner stages) requires EITHER:

(a) Grammar extensions for stage-by-stage algorithm decomposition: allow multi-symbol `output_stage_k` data declarations or per-stage compare-exchange iteration; OR

(b) A multi-pass stage-indexed encoding with variable loop bounds (`for k : 0..STAGES { for j : 0..stage_count(k) { ... } }`) — currently blocked by the const-loop-bound rule (the ACFG builder only `eval_const`s bounds); OR

(c) A first-class `stage_parallel` schedule primitive that takes a static stage count + per-stage worker mapping as a compile-time-known structure parameter, side-stepping algorithm-level decomposition entirely (this would be a stretch new schedule primitive).

This follow-up tracks the work to lift one of these constraints so example 12 can express its stage-parallel schedule at the algorithm/schedule level. Status: LOW priority, deferred-not-cancelled. Related: TASK-0179 (1D prefix scan), TASK-0044.05.01 (2D wavefront), TASK-0103 (const-flow).
