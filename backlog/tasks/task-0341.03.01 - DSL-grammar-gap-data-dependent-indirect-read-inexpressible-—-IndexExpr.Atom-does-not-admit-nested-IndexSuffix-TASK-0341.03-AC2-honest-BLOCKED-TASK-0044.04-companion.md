=== DSL grammar gap: data-dependent indirect read inexpressible (TASK-0341.03 AC#2 honest-BLOCKED + TASK-0044.04 companion) ===

Filed cycle 210 as the AC#2 honest-BLOCKED outcome for 17-spmv; description backfilled cycle 222 (TASK-0352 closure, cycle-219 architect P3.4 follow-up).

## Problem

The natural SpMV expression `y[i] = sum_k val[i][k] * x[col_idx[i][k]]` and the natural data-dependent-WRITE expression in 08-histogram (`histogram[bin] <-- inc(histogram[bin])` where `bin` is a loaded value) are both grammatically INEXPRESSIBLE in the v2 algorithm sublanguage.

## Root cause (grammar inspection)

`docs/grammar-algo.md` §1 fixes:

```
IndexExpr ::= AddExpr
AddExpr   ::= MulExpr (('+'|'-') MulExpr)*
MulExpr   ::= UnaryExpr (('*'|'/'|'%') UnaryExpr)*
UnaryExpr ::= ('-')? Atom
Atom      ::= IntLit | Ident | '(' AddExpr ')'
```

An `IndexExpr`'s `Atom` rule admits only `IntLit`, `Ident`, or a parenthesised `AddExpr`. A nested `IndexSuffix` (e.g. `col_idx[i][k]`) inside an `IndexExpr` (e.g. `x[...]`) is not in the grammar. The non-terminal `LValue ::= Ident IndexSuffix*` is reachable only at the top of a `DataflowStmt` LHS and as an `RValue`, NOT inside an `IndexExpr`. By design per PRD §6.2.4 (no conditionals; affine-only indexing into iter-vars + consts).

## Workaround in use (rectangular masked-accumulator)

Three in-tree examples ship the masked-accumulator workaround. All share the same shape: rectangular nest with a per-element conditional that gates the accumulator update:

- 17-spmv (TASK-0341.03 cycle 210): `spmv_step(acc, v, c, x_j, j)` returns `acc + v*x_j iff j == c else acc` — rectangular nest over (i, k, j).
- 08-histogram (TASK-0044.04): `bin_inc(acc, value, bin)` returns `acc + 1 iff value == bin else acc` — rectangular nest over (i, b).
- 04-prefix-sum (TASK-0039): `exclusive_add(acc, x, b, c)` returns `acc + x iff c < b else acc` — rectangular nest.

The workaround inflates iteration domain from O(data sparsity) to O(full grid) but compiles cleanly under every current backend.

## Proposed primitive (sketch — design is deferred work)

Extend `Atom` to include `LValue`:

```
Atom ::= IntLit | Ident | '(' AddExpr ')' | LValue
```

Downstream passes that rely on affinity (halo_inference, partition_inference, transfer_inject, boundedness) must learn to:

1. Treat data-dependent indices as opaque (no affine bound inference).
2. Emit conservative transfers (broadcast the entire indexed data symbol) when the address is data-dependent.
3. Reject distributed schedules over data-dependent indices unless the indirect access is constrained to a single partition (e.g. histogram's per-row indirection).

The conservative path mirrors what halo_inference's (B') rule does today for non-iv-affine indices: report and proceed without halo emission. The new surface needs the SAME conservative path, plus a fallback "broadcast the whole array" transfer for partitioned schedules.

## Honest scope LIMITS

- This is a DEFERRED grammar-extension epic, not a near-term task. The masked-accumulator workaround is correct and bit-deterministic. No production cell is blocked on this.
- Triggers for promotion: (a) a real example needs O(data sparsity) compute time, not O(full grid); (b) a multi-worker distributed schedule needs per-element data-dependent fan-in/out; (c) DSL-extension review consolidates this with the conditionals/while/break gap into a single grammar-v3 epic.
