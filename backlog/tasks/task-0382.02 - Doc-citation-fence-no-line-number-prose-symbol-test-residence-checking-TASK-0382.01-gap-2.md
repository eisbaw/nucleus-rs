## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Gap (2) deferred from TASK-0382.01 (which landed gap (1), the partial-path PREFIX resolver). 

The cycle-221 check-doc-citation-staleness-bare fence (and its TASK-0382.01 partial-path extension) only sees citations of the form <path>.rs:N — a basename or partial-path WITH a line number. It is structurally BLIND to the BARE-BASENAME-AS-LOCATION prose variant: a claim like "pinned by bin_rejects_multi_worker_* in tests.rs" or "the splice_after_repeat cell in transfer_inject.rs" that names a file (no :N) and asserts a SYMBOL / TEST resides there. 

This is the exact lie-shape the TASK-0383 mega-file split freshly produced (a cell named in prose moved to a sibling module while the prose kept the old basename) and that was caught ONLY by manual silent-sibling grep — see commit ec50108 (TASK-0389.01 fold-back fixed a stale splice_after_repeat cell name). 

Catching it mechanically needs symbol/test-name RESIDENCE checking (does the named test/fn still live in the cited basename, crate-scoped?), NOT a line-count range check. The HARD part is zero-FP: prose ambiguity about what token is a symbol name vs an ordinary word, and which .rs basename a bare mention refers to. Design carefully (e.g. restrict to the back-tick-quoted-ident + "in <base>.rs" co-occurrence shape, crate-scope the residence grep, SKIP on any ambiguity) or keep deferred. 

NEITHER this nor gap (1) is an FP risk on the current fence — purely additive coverage. Lower priority than keeping the fence zero-FP. Out of TASK-0382.01 scope by explicit decision (genuinely harder, separate zero-FP risk profile).
