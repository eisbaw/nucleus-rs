## Goal

Land example 10 — wavefront / diagonal LU — per PRD §9 row 10: 'Diagonal dependency, ordering, no SIMD'. The first example with a 2D dependency pattern where each output element depends on its NW + N + W neighbors (or analog), forcing an anti-diagonal sweep ordering.

## What this stresses (per PRD §9)

- Algorithmic: 2D dependency where iteration (i, j) depends on iteration (i-1, j), (i, j-1), and (i-1, j-1). The natural execution order is anti-diagonal (one diagonal at a time).
- Scheduling: naive (single worker, row-major) + diagonal-parallel (workers process consecutive elements ALONG a diagonal in parallel; diagonals execute sequentially).
- 'No SIMD' marker in the PRD: each diagonal-step kernel is scalar-dependent on its neighbors; vectorization is intentionally hard. This stresses the algorithm/schedule split — same kernel, two radically different traversal orders, both produce identical output.

## Closest template

`nuc-nucleus/examples/05-stencil/` — the existing 2D stencil example. Reuse:
- 2D data declaration pattern (`data img : f32[H][W]`).
- 2D loop nest in the algorithm.

The diff is the DEPENDENCY DIRECTION: 05-stencil is a pure REDUCE-OVER-NEIGHBORS (each output independent), 10-wavefront is a RECURRENCE (each output depends on prior outputs of the same array). Wavefront is the first example with a true loop-carried dependency along TWO axes. This may stress the algorithm-sublanguage's `pure` rule (PRD §6.2.1 single-assignment) — verify the wavefront can be expressed without violating SSA, likely by declaring output(i, j) as a function of output(i-1, j) + input(i, j) using a fresh write per cell.

## Honest scope

- The single-assignment rule (PRD §6.2.1) MAY rule out expressing wavefront as a simple `out[i][j] = f(out[i-1][j], out[i][j-1], in[i][j])` if the compiler interprets that as a self-referential write. The implementer should EXPECT to discover this and either (a) reframe the algorithm to fit SSA (separate intermediate arrays per diagonal) OR (b) file a language-extension sub-task. The latter is a known v2 limitation — see TASK-0179 for the related in-array prefix scan case.
- 'Diagonal-parallel' means workers process N elements along the SAME diagonal in parallel; the next diagonal waits on the previous. This is a barrier-synchronization pattern between successive diagonals.
- If the parallel schedule cannot be expressed in v2's sublanguage, that's a HONEST FAILURE — file it, ship naive only, mark the parallel schedule as a v3 / future-grammar follow-up.
