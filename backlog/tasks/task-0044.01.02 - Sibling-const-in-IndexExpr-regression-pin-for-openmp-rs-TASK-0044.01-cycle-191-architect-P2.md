## Goal

Port the existing `const_in_indexexpr_pthreads_async_resolves_to_literal_value` test from `nucleus/backends/pthreads-async/tests/skeleton.rs` to `nucleus/backends/openmp-rs/tests/single_worker_emit.rs` (or a new sibling file).

## Why

Cycle-191 architect review (TASK-0044.01) raised this as a silent-sibling per project memory `feedback-silent-sibling-defect`:

openmp-rs single-worker arm delegates through the same `pthreads_sync::render_single_worker_main` pipeline as pthreads-async. The cycle-35 `pthreads_sync::render_int_expr` const-in-IndexExpr fix (TASK-0245) reaches openmp-rs by the same construction. pthreads-async has a regression pin (cycle 36) that catches a future delegation-bypass drift; openmp-rs is equally susceptible but has NO equivalent pin. The `test_common::CONST_IN_INDEXEXPR_*` fixture is the single source of truth — the port is ~30 LoC.

## Acceptance criteria

1. `tests/single_worker_emit.rs` (or sibling file) carries a test mirroring pthreads-async's `const_in_indexexpr_pthreads_async_resolves_to_literal_value`.
2. The test consumes `test_common::CONST_IN_INDEXEXPR_ALGO_SRC` + `CONST_IN_INDEXEXPR_SCHED_SRC` + `CONST_IN_INDEXEXPR_ITERS_VALUE` + `CONST_IN_INDEXEXPR_ITERS_IDENT` (no fixture duplication).
3. Pins (a) the resolved const literal appears at the IndexExpr arithmetic site in openmp-rs's emitted main.rs; (b) the bare const ident does NOT appear anywhere.

## Honest scope

Single-worker only — multi-worker const-in-IndexExpr coverage is naturally subsumed by the cycle-191 byte-identical-vs-pthreads-sync invariant on the same emitter, so the test is structurally the same shape as pthreads-async's.

## Forward-carried context

- The `test_common` dev-dep is already wired into openmp-rs/Cargo.toml at cycle 191.
- pthreads-async's test (cycle 36) is the line-by-line template — see `nucleus/backends/pthreads-async/tests/skeleton.rs::const_in_indexexpr_pthreads_async_resolves_to_literal_value`.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
## Cycle 193 — Closed as REDUNDANT (no code change)

Empirical investigation in cycle 193 found the cycle-191 architect filing conflated two distinct silent-sibling concerns:

1. **Single-worker delegation drift** (openmp-rs single-worker arm wrapping the delegated render_single_worker_main) — REAL concern.
2. **Multi-worker independent renderer drift** (the cycle-36 pthreads-async test's scope) — applies to backends with INDEPENDENT multi-worker codegen.

The cycle-36 pthreads-async test (`const_in_indexexpr_pthreads_async_resolves_to_literal_value`) uses the multi-worker fixture `test_common::CONST_IN_INDEXEXPR_*` (workers = {host, w0}) and exercises pthreads-async's MULTI-WORKER codegen path through the shared multi_worker_walker. It exists because pthreads-async's multi-worker codegen is INDEPENDENT and could diverge from pthreads-sync's render_int_expr cycle-35 fix.

**Why redundant for openmp-rs single-worker (cycle 193 finding):**

- openmp-rs's only landed arm is single-worker (cycle 191).
- Single-worker delegates to `pthreads_sync::render_single_worker_main` byte-for-byte.
- `single_worker_emit.rs::single_worker_real_example_emits_byte_identical_to_pthreads_sync` (the cycle-191 byte-identical test on 01-elementwise-add/naive real fixture) catches ANY delegation-bypass drift, including const-in-IndexExpr regressions, by structural construction.
- The multi-worker fixture cannot reach openmp-rs's single-worker arm — running emit() on workers={host,w0} hits the multi-worker ContractGap.

**Forward-carry to TASK-0044.01.01:** when openmp-rs's multi-worker arm lands (via rayon-scope codegen + multi_worker_walker consumption), an INDEPENDENT const-in-IndexExpr pin BECOMES needed because the multi-worker arm is independent codegen, exactly the cycle-36 pthreads-async pattern. Added as a forward-carried lesson on TASK-0044.01.01 (cycle 193).

**Same-shape observation for mp-tcp-poll (cycle 192):** mp-tcp-poll's single-worker arm has byte-identical-vs-mp-tcp-bufsync. Same byte-identical test catches the same drift class. No const-in-IndexExpr pin needed for mp-tcp-poll single-worker either. When TASK-0044.02.02 (mp-tcp-poll multi-worker) lands, file the same pin under its scope.

**Cycle 193 lesson (orchestrator memory):** reviewer subagents can mis-classify a silent-sibling concern by aliasing TWO distinct delegation-vs-independent-codegen scenarios. The defense is to verify the FIXTURE shape (single-worker vs multi-worker) matches the BACKEND ARM the silent-sibling claim targets. This is a refinement of feedback-implementer-disclosure-mechanism-wrong: the mechanism-error generalises to reviewer fixture-fit reasoning too.
