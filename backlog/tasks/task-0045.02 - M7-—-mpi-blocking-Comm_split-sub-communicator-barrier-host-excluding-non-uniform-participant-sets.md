## Implementation Plan (cycle TASK-0045.02)

DESIGN — shared substrate (backend_common::mpi_plan::plan.rs), serves BOTH MPI backends.

1. Plan::build: STOP rejecting non-whole-world barriers. Instead, partition barrier_participants into whole-world (== all_used) and strict-subset sets. Assign each DISTINCT strict-subset participant set a deterministic non-negative color (BTreeSet ordering -> enumerate index, 0-based). Store split_groups: Vec<(color, BTreeSet<WorkerId>)> + a map BarrierId -> SplitKind {WholeWorld | Subcomm(color)}.

2. Plan::emit: AC#2 crux. After write_universe_init + the size guard, BEFORE `match world.rank()`, emit ONE `let split_<color> = world.split_by_color(if [<participant ranks>].contains(&world.rank()) { Color::with_value(<color>) } else { Color::undefined() });` per distinct subset group. Every rank (participant or not) reaches every split in identical order (Color::undefined -> None for non-participants). Comm_split is COLLECTIVE over COMM_WORLD; emitting outside the arms is the deadlock-safety invariant.

3. render_worker_arm barrier bindings: whole-world barrier -> `let bar_<tag> = WorldBar::new(&world);` (unchanged). Subcomm barrier -> `let bar_<tag> = SubcommBar::new(&split_<color>);` borrowing the pre-computed Option<SimpleCommunicator>.

4. Prelude (per-backend text, identical in both): add a `SubcommBar` wrapper over `&Option<SimpleCommunicator>` whose `.wait()` calls `subcomm.barrier()` IFF Some (participant); None (non-participant) is a no-op for that barrier. Keep the walker emit `bar_<tag>.wait()` unchanged (uniform call surface).

5. NOT a new MpiRendezvous method: Comm_split text is identical for blocking + buffered, so it lives in shared Plan::emit + the (identical) SubcommBar prelude addition. No trait-method justified.

6. Color non-negativity: Color::with_value panics on negative; 0-based enumerate index is always >= 0. Deterministic by BTreeSet ordering of distinct subsets => reproducible emit.

AC#3: barrier smoke fixture tests/mpi/barrier-smoke/ (mirror rsmpi-smoke) proving split_by_color + sub-comm barrier links+runs under mpiexec; new `just check-mpi-barrier-smoke`. Value-correct synthetic schedule: investigate whether the .nuc schedule language can express a strict-subset barrier for mpi-blocking; if not (cross-partition-reducer-unreachable wall), file a precise follow-up + leave that arm to the real consumer (example 9, TASK-0046.01) — honest partial.

GATE: build/clippy/test/test-release/e2e (385/328/0/57/0 must hold) + check-mpi + check-mpi-nonblocking byte-exact + new smoke under mpiexec.

GOTCHAS / SUBTLETIES:
- COLLECTIVE-ORDERING is the whole correctness story: MPI_Comm_split is collective over COMM_WORLD. A non-participant rank that skipped the split deadlocks the participants inside MPI_Comm_split. That is why the split lives OUTSIDE the rank arms (every size==n rank runs it). The sub-comm barrier() itself is collective ONLY over the participant sub-group, so a None-holding non-participant doing NOTHING is correct (not a skipped collective).
- FAITHFUL FIXTURE: a worker is a barrier participant iff petri_to_events added the Event::Sync to ITS list AND listed it in participants. The OLD reject test mutated only participants (left host emitting bar_<tag>.wait() with no binding => would not compile). New host_excluding_02_split helper ALSO removes the host Sync events => the consistent shape of a real {w0}-only barrier.
- COLOR NON-NEGATIVITY: Color::with_value panics on negative; 0-based enumerate index is always >= 0. Chose BTreeSet-content order over SyncTag-first-seen order so a participant-set color is a pure function of the set.
- count assertion footgun: bare "split_by_color(" matches the SubcommBar prelude DOC comment too; the test matches the call shape "= world.split_by_color(if " instead.
