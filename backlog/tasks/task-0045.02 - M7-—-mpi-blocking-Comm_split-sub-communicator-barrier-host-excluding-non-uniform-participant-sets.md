## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Forward-linked from TASK-0045.01: the multi-worker SPMD arm implements ONLY whole-world MPI_Barrier (participants == all used workers, e.g. 02-split, 03-reduction, 06-separable). The M7 foundation flagged Comm_split as UNPROVEN; mpi-blocking currently rejects non-whole-world participant sets loud (EmitError::UnsupportedFeature, forward-linking this task). No shipped sync multi-worker schedule needs it today, so this is latent until an example with a compute-only/host-excluding barrier lands.

DESIGN (AC#2 is the correctness crux): emit the MPI_Comm_split OUTSIDE the match world.rank() arms so EVERY rank calls split in identical order with the same arg shape (color = participant?1:MPI_UNDEFINED, derived from barrier_participants). Non-participant ranks split into a throwaway/undefined comm and must NOT call the sub-comm barrier; participants call subcomm.barrier(). A split is collective over COMM_WORLD — all ranks must reach it, so it cannot live inside a per-rank arm.
