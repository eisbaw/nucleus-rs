## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Cycle-17 review-gate (commit 5719897) QA + architect both surfaced: the emitted src/main.rs from pthreads-async (and any future single-binary backend that delegates to pthreads_sync::render_single_worker_main) carries the literal header:

    //! Generated by the pthreads-sync backend (TASK-0020, M1).
    //! Do not edit; rerun `nucleus build` to regenerate.

…even when produced via --backend pthreads-async. The header is correct for byte-identicality (delegation means literal-string identity, which IS the cross-backend differential invariant on naive schedules), but it is a small provenance lie that confuses any developer inspecting a pthreads-async emit.

This is an instance of the recurring 'comment/doc lies' defect class (feedback-comment-doc-lie-recurring). The fix options:

(a) Emit a backend-agnostic header (e.g. '//! Generated by the nucleus pre-compiler.') in the SHARED render_main_rs. This preserves byte-identicality across backends; requires touching the shared renderer and updating any test that pins the current literal.

(b) Pass a backend-name parameter into render_single_worker_main so each delegator stamps its own provenance. This BREAKS byte-identicality (the header differs) — which IS the property the cross-backend differential tests rely on. Wrong direction.

(c) Leave it. The lie is contained to a leading comment, not to runtime behaviour.

Recommend (a): one shared neutral header + update the tests in compiler/tests/e2e_example_*.rs and pthreads-sync/tests/emit.rs that grep for 'pthreads-sync backend' literal. The byte-identicality invariant is preserved (all backends emit the same neutral header).
