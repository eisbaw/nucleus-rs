## Done — orchestrator-direct cycle (with partial scope)

Three sub-pieces, three resolutions:

### (a) loop_var duplication — RESOLVED: defensive-assert path

Kept `CheckFrame.loop_var: String` (carried by value); added `debug_assert_eq!(var.as_str(), frame.loop_var.as_str(), ...)` at all three backend emit sites where `var` (NameTables) and `frame.loop_var` are both in scope:
- `nucleus/backends/pthreads-sync/src/lib.rs:902-916` (single-worker render_event).
- `nucleus/backends/mp-tcp-bufsync/src/lib.rs:770-781` (mp-tcp per-worker render_event).
- `nucleus/backends/pthreads-sync/src/multi_worker.rs:692-704` (multi-worker render_worker_events).

Dev builds catch projection-layer divergence loudly; release builds skip the check (zero cost on the codegen path). Alternative considered: drop the field and look up via NameTables at emit time — rejected because it would require threading NameTables through `collect_count_check_frames` (an EventList walker), expanding API surface for marginal architectural gain.

`CheckFrame.loop_var` docstring (event.rs:552-570) rewritten to document the invariant + the chosen path + the alternative rejected. Anchored in the doc-lie recurring class — the docs match the actual emit-site asserts.

### (b) test placement — DEFERRED (low impact)

`check_frame_codegen.rs` stays in `compiler/tests/` for now. Moving to `backends/pthreads-sync/tests/` would close a backwards dev-dep arrow (compiler -> pthreads-sync for test only) but is a refactor of test file structure, not a correctness fix. Filed as TASK-0225 if it ever bites — for now the dev-dep is documented + harmless.

### (c) + (d) on_violation=Log/Count + multi-worker reject negative tests — OBSOLETE

When TASK-0221 was filed, Log/Count + multi-worker check_frame all returned `EmitError::ContractGap` (fail-loud reject). The architect's concern was that no test pinned the reject behaviour.

After TASK-0052.04 (commit c37baf6) wired Log + Count on tier-1 sync backends AND TASK-0052.05 (commit 42159f6) wired multi-worker check_frame, ALL three code paths the rejects pointed at are now legitimate codegen — the ContractGap rejects no longer fire. The "missing negative test" concern is moot because there's no reject path left to test.
