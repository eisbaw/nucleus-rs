=== CORRECTION (orchestrator, cycle of commit cbbe0c9) — SUPERSEDES the cross-crate-link guidance in this task's Description ===

RETRACT the Description sentence that lists "cross-crate `crate_name::path::Item`" among the sanctioned PROPER-LINK forms. That is WRONG and was a propagated comment-doc-lie from the backend-common slice (the FireBinding "resolved" claim, falsified by architect review + orchestrator href-grep).

CORRECT RULE for this nucleus-compiler arm:
- A cross-crate intra-doc-link to a DEPENDENCY (e.g. nucleus_compiler -> some other crate) does NOT resolve under `cargo doc --no-deps`. rustdoc renders it as a literal-path href (href="othercrate::path::Item") that 404s, and emits NO warning — broken_intra_doc_links is structurally BLIND to it. So the `-D broken_intra_doc_links` oracle alone will PASS a dead cross-crate link.
- Therefore: for any target NOT in the crate being documented, use a BACKTICK code span, NOT a [link](other_crate::path). Proper links are only honest for SAME-crate targets (crate::path::Item, crate::Enum::Variant) and items reachable in the doc invocation.
- nucleus-compiler is the ROOT crate here, so most of its own types ARE same-crate (crate::...) and CAN be properly linked; only references OUT to its dependencies need backtick.

VERIFICATION the oracle alone does NOT give you (architect P2): after the per-crate doc build, grep the generated HTML for dead hrefs:
  grep -rho 'href="[a-z_]*::[^"]*"' nucleus/target/doc/nucleus_compiler/   # MUST be empty
Any href containing `::` is a guaranteed-dead cross-crate link. Run this under BOTH default and --document-private-items. When the deferred `cargo doc --no-deps --workspace` arm is finally ADDED to just ci, its DoD MUST include this dead-href grep assertion (the lint cannot catch this class).
