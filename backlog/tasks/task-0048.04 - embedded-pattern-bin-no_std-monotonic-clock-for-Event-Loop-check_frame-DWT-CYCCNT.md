## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Carried from parent TASK-0048 'Forward-carried lesson from TASK-0052.02'. The tier-1 backends emit std::time::Instant::now() for the latency_max check-frame measurement; that does NOT exist on bare-metal Cortex-M (no_std). TASK-0048.01's emit_bin currently REJECTS any Event::Loop carrying a check_frame with a typed EmitError (inherited from render_run_body's M9 guard) — the naive schedules carry none, so this is latent. When an embedded schedule with a 'check loop' real-time frame is targeted, the bin path needs a no_std clock primitive: candidates are the Cortex-M7 DWT CYCCNT cycle counter (convert cycles->ns via configured SystemCoreClock) or SysTick. Also: PRD §6.3.5 says on_violation=panic on tier-3 BRICKS the device — prefer log/count (follow TASK-0052.04's tier-1 contract). Until then the EmitError rejection is the honest behaviour.

## Final summary (cycle complete — all ACs met + verified)

### Clock design (AC#1): Cortex-M SysTick via NucleusShim::monotonic_ns trait method.
- SysTick (24-bit down-counter @ 0xE000_E010/14/18), NOT DWT CYCCNT. Reason: docs/check-loop-latency-max.md §3 + carried context warned DWT CYCCNT may not advance under Renode's non-cycle-accurate timing; PRD §6.3.5 permits either. EMPIRICALLY CONFIRMED SysTick advances under Renode (see AC#3).
- Shim-hook (trait method) over direct-register-in-lowering: the shim IS the PRD §6.3.5 'backend-specified monotonic clock' seam. Keeps Cortex-M register details inside the shim; the generic render_event lowering only calls shim.monotonic_ns(). StubShim returns 0 (M9 honestly inert, AC#6 'no real timing'); Usart1Shim reads SysTick and accumulates ticks into a monotonic ns reading.
- cycles->ns calibrated to SYSTEM_CORE_CLOCK_HZ = 64_000_000 (STM32H7 HSI reset default), documented as a calibration assumption; the ns figure is NOT physically meaningful under Renode (verifying lowering correctness + clock-advance, not timing fidelity).
- ATOMIC WIDTH: did NOT need AtomicU32/U64 — the SysTick accumulator is plain struct state (single-core, no cross-thread sharing on a bare-metal single-MCU firmware). The tier-1 AtomicU64 Drop-guard reporter is NOT ported (AtomicU64 absent on thumbv7em; Drop never fires on a spinning MCU).

### on_violation tier-3 policy (AC#2): log fully lowered; panic + count REJECTED (typed EmitError), NOT silently remapped.
- log: shim.report_violation(b"<var>", measured, threshold) trait method = a per-violation UART line (no_std analogue of eprintln!). New 6th trait method.
- panic: rejected — bricks the MCU (PRD §6.3.5). ViolationKind defaults to Panic at sched-lower, so an embedded check loop MUST pick on_violation=log explicitly.
- count: rejected — the tier-1 Drop-guard summary fires at main() return, but a bare-metal firmware spins forever (no Drop); docs §3. Forward-linked TASK-0048.08.
- NucleusShim grew 4 -> 6 methods (+monotonic_ns +report_violation). Updated trait/Stub/Usart1Shim docstrings + shim_trait_declares_all_six_methods test + tests.rs method list (doc-lie discipline).
