## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Carried from parent TASK-0048 'Forward-carried lesson from TASK-0052.02'. The tier-1 backends emit std::time::Instant::now() for the latency_max check-frame measurement; that does NOT exist on bare-metal Cortex-M (no_std). TASK-0048.01's emit_bin currently REJECTS any Event::Loop carrying a check_frame with a typed EmitError (inherited from render_run_body's M9 guard) — the naive schedules carry none, so this is latent. When an embedded schedule with a 'check loop' real-time frame is targeted, the bin path needs a no_std clock primitive: candidates are the Cortex-M7 DWT CYCCNT cycle counter (convert cycles->ns via configured SystemCoreClock) or SysTick. Also: PRD §6.3.5 says on_violation=panic on tier-3 BRICKS the device — prefer log/count (follow TASK-0052.04's tier-1 contract). Until then the EmitError rejection is the honest behaviour.
