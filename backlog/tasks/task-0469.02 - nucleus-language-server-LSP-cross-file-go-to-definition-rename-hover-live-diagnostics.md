## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Zero-friction editing inside the class. The shared name table between the two sublanguages makes an LSP unusually tractable and unusually valuable. Capabilities, in priority order: (1) live diagnostics surfacing the existing typed errors (unplaced kernel, unknown name, missing transfer directive, capability mismatch) as the user types; (2) go-to-definition across the algo/sched boundary (schedule place/loop/transfer names jump to the algorithm declaration); (3) hover showing inferred facts from the sidecars (per-worker bands, halo widths, synthesised transfers) — explainability inline; (4) cross-file rename of a kernel or loop variable, which today silently invalidates every schedule that references it (closes the rename-breaks-schedules risk called out in PRD section 13). Reuse the chumsky parser and existing pass machinery via a library entry point rather than re-implementing analysis; prefer a thin LSP shell over the compiler crate. Depends on 0469.01 only for editor packaging, not for analysis.
<!-- SECTION:DESCRIPTION:END -->
