## Goal

Land the seventh tier-1 backend crate `nucleus/backends/mp-uds-event`: workers are OS processes, transport is Unix domain sockets, notify is mio/epoll event readiness, supports async + buffer (per-(DataId, SeqTag) bounded queue). PRD §7.1 row 7.

This is the ASYNC-side sibling of mp-tcp-event: same multi-process + mio + ring-buffer substrate, but uses Unix domain sockets (`std::os::unix::net::UnixListener` / mio's `UnixListener` wrapper) instead of TCP loopback. UDS is faster than TCP-loopback (no IP stack), supports SCM_RIGHTS for fd-passing (not exercised in v2), and uses filesystem paths instead of port numbers — eliminating the port-picker dance entirely.

## Closest template

`nucleus/backends/mp-tcp-event` is the structural template:
- Same multi-binary output + multi-worker mio reactor.
- Same per-(DataId, SeqTag) ring buffer + epoll readiness gating.
- Same emit() signature + EmitResult shape (worker_bins + wire_rs + runtime_rs + run_sh).

The diff is the transport layer: UnixListener.bind(\"<path>/worker-N.sock\") instead of TcpListener.bind(\"127.0.0.1:<port>\"). mio's UnixListener / UnixStream share the Source trait with TcpListener / TcpStream so the reactor surface stays identical.

This is also a CANDIDATE FOR LIFTING. If the mp-tcp-event reactor / Plan::build code is parametric over the listener type via a trait, the lift may be cheap. If not, the implementer should ASSESS THE LIFT EFFORT BEFORE COPYING and file a separate lift-task if copy-paste exceeds ~200 lines.

## Honest scope

- mio's UnixListener wrapper requires the `os-ext` feature in some mio versions. Check Cargo dependency.
- SCM_RIGHTS / fd-passing is NOT in scope. UDS is used as a stream socket, identical surface to TCP.
- The cross-backend differential should gain mp-uds-event vs mp-tcp-event as a fourth ASYNC + BUFFERED row (in addition to pthreads-async). This is genuinely new ground; any divergence will surface defects in either the new UDS code OR the existing reactor that were hidden by TCP-only testing.
- run.sh path-cleanup: the e2e harness deletes `target/e2e-matrix/run-*/` on success (memory project-e2e-harness-scratch-lifecycle); the UDS sockets need to live under that scratch dir so cleanup is automatic.
