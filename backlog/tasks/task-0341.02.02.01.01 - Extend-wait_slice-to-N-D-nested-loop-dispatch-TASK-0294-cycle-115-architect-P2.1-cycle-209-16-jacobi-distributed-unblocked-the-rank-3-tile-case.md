## Root cause (5-backend variant — THIS TASK)

`backend-common/src/multi_worker_walker/wait.rs:282-293` carries a rank-3+ guard:

    if tile.bounds.len() > 2 || (tile.bounds.len() >= 2 && ty.dims.len() > 2) {
        return Err(EmitError::ContractGap(format!(
            "Wait of data {data:?}: tile rank {} and data dim rank {} \
             exceed the 2D row-loop slice-paste's supported shape ..."
        )));
    }

16-jacobi/distributed constructs a rank-3 tile (partition=rows on the spatial y-axis of a 3D `field[ITERS+1][H][W]` data symbol). The guard's docstring claim 'No shipped schedule constructs this today' was true at cycle 115's landing but became false at cycle 209's landing.

## Proposed shape

Extend `wait_slice` from the current 2-case dispatch (`Flat` 1D + `Rows` 2D) to an N-D nested-loop emit:

- Add a `WaitSlice::NestedRows { outer_axes: Vec<(usize, usize)>, ... }` variant carrying the per-axis (lo, hi) range for each partition-bound axis.
- `render_wait_assign` emits N nested `for` loops, one per partition-bound axis, with the innermost loop body being the existing copy_from_slice.
- The Flat (rank-0 partition) and Rows (rank-1 partition, the 2D case) paths stay — both are special-cases of NestedRows; the optimisation is in the rendered output, not the IR shape.
