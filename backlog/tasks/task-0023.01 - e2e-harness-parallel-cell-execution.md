## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0023 ships sequential cell execution. cargo build saturates cores for one cell at a time; running cells in parallel mostly contends for the build cache. As the matrix grows past pthreads-sync (M3+), evaluate spawning N=ncores worker tasks with separate target dirs per cell.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Forward-carried from TASK-0182 (Done, commit 5735b19): the shared-tree CWD race that blocked safe concurrent harness runs is FIXED via a process-wide run-id path segment (nucleus/target/e2e-matrix/<run-id>/<cell>, e2e-determinism/<run-id>/<cell>__<label>), computed once in Paths::discover. This is a PREREQUISITE for parallel-cell execution and is now in place: WITHIN a single harness process all cells already get unique stable paths under one run-id, so parallelising cells inside one process is safe w.r.t. scratch-dir collisions WITHOUT further per-cell isolation work. Deliberately chose run-id over an flock lock precisely so this task is not serialised. NOTE: TASK-0182 added gate-only NUC_E2E_FORCE_SHARED_RUN_ID (test seam) and a 24-way concurrency stress test (tests/concurrency_stress.rs) that can be extended to assert the in-process parallel executor stays infra-race-free. Also: the end-of-run finalize_run_scratch cleans the per-run tree on success — a parallel executor must keep the single end-of-run cleanup (do NOT clean per-cell, sibling cells share the run-id root).
