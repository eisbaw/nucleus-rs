## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0054 cycle 201 follow-up. The embedded_multimcu schedule at nuc-nucleus/examples/14-hearing-aid/schedules/embedded_multimcu.sched.nuc references per-frame peripheral kernels (fe_capture / rf_receive / fe_emit / rf_transmit) that the cycle-201 tier-1 bulk-IO algorithm does NOT declare. The schedule file is preserved AS-IS as the M11 design target; all 7 e2e cells are currently [[skip]]'d (TASK-0054.01 M11-deferred reason).

When M11 (multi-MCU Renode co-simulation) lands, this task delivers:

1. Algorithm extension to declare the per-frame peripheral kernels. Likely paths:
   (a) Second algorithm file (`prog.algo.M11.nuc` or similar) with the stateful peripheral kernels; the tier-1 vs M11 worlds share `mix2` + `denoise` but differ in IO.
   (b) Algorithm-level `tier` discriminator that selects between bulk-IO and per-frame-IO declarations at compile time.
   (c) Add fe_capture/rf_receive/fe_emit/rf_transmit kernels back to the SHARED algorithm; tier-1 schedules + kernels.rs would need to deal with them (likely stub them as no-op variants of load_*/save_*).
   
   Option (a) is cleanest but introduces a second algorithm file (more code to maintain). Option (b) is least disruptive but requires algorithm-sublanguage extension. Option (c) requires per-process state for the stateful kernels that breaks multi-process backends (mp-tcp-bufsync / etc.).

2. Stateful per-frame kernel implementations in kernels.rs (or a new kernels.M11.rs). The fe_capture/rf_receive kernels track a call-count via AtomicUsize and read frame[counter] from canned bins; fe_emit/rf_transmit write frame[counter] to accumulating buffers flushed on Drop. ONLY safe for single-process M11/Renode mode.

3. Renode multi-MCU substrate (M11 milestone scope — depends on TASK-0064 Renode integration). Three MCUs: FE_MCU + DSP_MCU + RF_MCU connected over SPI.

4. Promote all 7 currently-[[skip]]'d embedded_multimcu cells to [[required]] once the schedule lowers + runs bit-identical against an updated reference impl.
