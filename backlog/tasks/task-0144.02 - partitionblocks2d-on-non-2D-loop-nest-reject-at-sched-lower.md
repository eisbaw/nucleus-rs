## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0144 Stage 3 follow-up: partition=blocks2d only makes sense on a 2D loop nest. Today it is accepted on any loop. Reject when the surrounding loop nest is not 2D (or when the partitioned axis lacks a sibling axis with a paired partition). Detection needs cross-directive context (the loop's place in the nest), not just per-loop option validation — so this is a schedule-validate pass on the IR, not a single-directive check.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Forward-carried from TASK-0144.01 cycle 65: this check CANNOT live in sched/lower.rs::lower_loop the way Stage 2 (UnrollNotDivisibleByBlock) and Stage 3 (.01 VectorizeNotDivisibleByBlock) do. Those two are pure single-loop payload-only checks. partition=blocks2d-on-non-2D-nest needs cross-loop context: how many *enclosing* loop directives there are and which axes they partition. That information is available in the schedule IR (ir.loops as a whole, walked after lower_loop completes), or in the algorithm AST (the loop nest topology). Recommended placement: a schedule-validate pass that runs AFTER lower_loop finishes building ir.loops, so it can see the whole picture; reject with a new SchedLowerErrorKind variant routed through the same classification table (Independent | yes | never). Do NOT try to retrofit this into lower_loop.

Cycle 66 sizing finding: this task as written PRESUPPOSES Blocks2d has downstream semantics. Audit (TASK-0249) showed PartitionKind::Rows and PartitionKind::Blocks2d are BOTH silently inert today — parsed, lowered, never consumed. The narrower 'reject non-2D nest' fix would leave the 2D-nest Blocks2d case as a silent no-op. .02 must wait for TASK-0249 to land semantics or a loud-reject before becoming meaningful.
