## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Lower the for..until node to IR/ACFG keeping the compile-time cap N so the Petri net still unrolls to N (acfg_to_petri.rs ~360). KEYSTONE soundness argument (architect GO, design review cycle-254): boundedness is an over-approximation proved on the FULL-N unroll, and any early-exit prefix 0..k (k<=N) is a sub-trace of a bounded net, hence bounded a fortiori — the convergence predicate is ANALYSIS-INVISIBLE to the Net. Rides the existing decoupling: the Net unrolls but the EventList projection does NOT (acfg_to_petri.rs ~55-66), so the loop structure + a new break-condition survive to codegen. The runtime condition lowers to an early-exit guard within the capped N. TWO P1 SEMANTICS TO PIN HERE (not defer): (1) CUMULATIVE-BUFFER FINAL-READ: 16-jacobi double-buffers; on early-exit at k the current generation sits in buffer k%2 and the final gather MUST read the LAST-EXECUTED generation, not generation-N — gated by the S0 spike finding; add a behavioral test that early-exits at known k and checks the gather is generation-k. (2) CAP-HIT-NOT-CONVERGED must be OBSERVABLE (no silent stop-at-N that looks identical to converged — feedback-option-none-skip-arm-silent-drop). Decide cap-hit semantics: diagnostic / sentinel / recorded did-not-converge signal.

=== Forward-carried from S0 spike (TASK-0341.02.01.01) + architect review, cycle-255 ===
EMPIRICALLY-GROUNDED design consequences for THIS slice:
1. FINAL-EXTRACTION SLICE INDEX MUST BE RUNTIME. The shipped 16-jacobi reads a HARD-CODED slice field[ITERS] (generated main.rs:22 field[(4)*64+...]). On early-exit at k<N, slice ITERS is unwritten (all-zero) — proven by the spike. The convergence variant must extract from field[k] where k = the break generation (the loop var t at break). Because field is a FULL (ITERS+1)-slice history array (NOT a 2-slice double-buffer), generation-k is always materialized in slice k and is correct; only the extraction slice index changes to runtime. Thread the captured break-generation into the extraction loop.
2. THE CROSS-ITERATION READ INDEX NEEDS NO CHANGE (architect P3): (t+ITERS)%(ITERS+1) always evaluates to t-1 at t>=1 (the immediately-prior, always-written slice), independent of where the break lands. So the fix is FINAL-EXTRACTION-ONLY; do NOT touch the step read index.
3. SCALING IS A KEYSTONE CONCERN, NOT S5 PERF (architect P2, re-framed): the full-history buffer is (N+1)*H*W. For a data-dependent convergence loop N is the WORST-CASE compile-time cap; the Petri net unrolls to N (the boundedness/soundness keystone), so a large N inflates the unrolled net the boundedness gate must replay — couples to S4 tractability, NOT S5 runtime memory. A 2-slice double-buffer may be LOAD-BEARING for keystone tractability at large N, not an optional optimization. Decide the buffer model (full-history vs double-buffer) HERE in S4 with the Petri-unroll bound in mind; if double-buffer, the consequence-1 final-read becomes field[k%2] and the cumulative classifier (sidecar.rs:704-762, index-shape based) must be re-checked.
4. DEPENDENCY ADDED: S0b (TASK-0341.02.01.09) pins the codegen invariant this slice depends on with a real workspace test — land it before/with S4 so substrate drift fails loud.
