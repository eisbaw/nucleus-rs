## Description

Concrete realisation of the 0455.06 AC#2 diagnostics-UX audit for the two highest-value error surfaces, both of which already KNOW the answer they should suggest. (1) Capability rejection: when a schedule is refused because the backend lacks async/buffer/notify, also print which backends WOULD accept this schedule — the data is sitting in the capabilities matrix the compiler just consulted (Appendix C tabulates exactly this). (2) Placement errors: an unplaced-kernel error should propose the place line to add; a placement of a kernel the algorithm does not define should suggest the closest real kernel name (did-you-mean, building on TASK-0096 / TASK-0198 fuzzy match). Every fix hint must be exercised by a test pin so it cannot rot into a bare error. This is the difference between a compiler that refuses and one that teaches — load-bearing for the preferred-language goal (parent epic TASK-0469).
