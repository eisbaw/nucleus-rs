## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0340.08 cycle 184b architect P2.4 finding: the proptest_petri.rs generators in slice 9 (Petri-net + ACFG) are deliberately narrowed for state-space-oracle tractability. This restricts the epistemic value of three properties:

- **p.1** (acfg_to_events emits only Fires from Operation-only ACFG) is generator-trivial — the ACFG generator never emits Push/Wait/Sync/Repeat, and acfg_to_events emits Fire from Operation nodes by construction. The property is a regression guard against the projection emitting unexpected non-Fire kinds, not a test of the AC#3 nominal acyclic-per-worker claim.
- **b.*** (boundedness) is missing weight>1 arc cases —  capacity guards behave qualitatively differently when an arc moves >1 token per fire.
- **d.*** (deadlock) is missing Push/Wait/Sync scheduling — the deadlock pass's nontrivial defects most likely surface under cross-worker synchronisation, which Operation-only ACFGs do not exercise.

The cycle-184 narrow generators were the right shape for the AC#3 'at least 3 properties per pass' headline + ≤10_000-marking oracle cap. Widening them is forward work, not slice-9 fix.

## Scope (proposed; finer slicing welcome)

(1) Petri-net generator: extend to allow weight∈{1,2,3} on arcs, with state-space oracle's STATE_SPACE_CAP raised proportionally OR oracle made step-bounded (N=50 firing steps even if exhaustive enumeration would diverge).

(2) ACFG generator: extend to allow Repeat (nested up to depth 2), Sync (cross-worker barrier), Push/Wait pairs on a 2-3 worker set. Each addition must keep acfg_to_petri::acfg_to_net total under MAX_PLACES×MAX_TRANSITIONS ≈ 8×8 for oracle tractability.

(3) New properties (or extensions of existing ones):
- b.4: with weight>1 arcs, check_bounded must agree with bounded-reachability oracle on the cap=1 / weight=2 sharp-edge case.
- d.4: with Push/Wait pairs, check_deadlock_free must agree with full-state-space deadlock-enumeration (NOT the cycle-184 per-order replay oracle).
- p.4: with Sync + multi-worker generator, acfg_to_events must produce a per-worker event list whose Sync events match the global barrier count.
