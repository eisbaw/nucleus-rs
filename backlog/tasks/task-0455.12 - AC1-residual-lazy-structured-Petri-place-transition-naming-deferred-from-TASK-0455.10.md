## Description

Deferred from TASK-0455.10 (which landed the AC#2 whole-net-clone elimination behaviour-neutral). AC#1 asked: Place/Transition carry no eagerly-built String names; format on demand for error/DOT only.

WHY DEFERRED (measured, not assumed): a structured-id refactor of Place::name / Transition::name is NOT behaviour-neutral-cheap. The name strings are part of the public Place/Transition API and are consumed SEMANTICALLY (not just for DOT/error) by 60+ test reads (p.name.starts_with("buf_"), t.name.starts_with("sync_"), buf_markings.insert(p.name.clone(),..), assert_eq!(place_name,"buf")) and 155 hand-built add_place/add_transition string-literal call sites across tests/{net_soundness,petri,boundedness,deadlock,proptest_petri}.rs. The buffer-place name buf_{data_name}_seqN fundamentally interpolates a runtime data-symbol NAME looked up from acfg.name_data — not a structured id formattable without threading the ACFG into Display. Any enum form needs a Custom(String) escape hatch that does NOT remove the strings on the hot buffer/control path.

MEASURED HEADROOM (the reason it is low-priority): at the largest currently-compiling net (07-matmul distributed8, T=4149/A=65722), the name heap strings are ~1.9 MB held-for-net-lifetime and do NOT move peak RSS (peak ~88.6 MB is set by the 10MB driver binary + backend codegen + allocator arenas, NOT the gate). TASK-0455.10s AC#2 already removed the dominant transient cost (~21 MB of churn across up to 5 whole-net clones at that N).

TO CLOSE: needs either (a) a structured PlaceName/TransitionName enum with on-demand Display + a rewrite of all 60+ semantic name reads to structured fields, or (b) string interning to collapse the N unrolled op_kN/push_seqN/ctl_w_slot duplicates. Both are larger-surface than a behaviour-neutral wave task; pick up when a much larger N actually makes the 1.9 MB matter (the NeedsExpansion residual).
