## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0434 cycle-251 architect P3-2. for_loop_var() (algo/parser.rs) anchors the keyword-collision diagnostic at VAR by take_until(just(quote-brace)) so its error out-reaches the trailing block-brace in chumsky 0.9 furthest-position merge. EDGE CASE: on TRUNCATED input with no opening brace (e.g. `for loop : 0 .. N` at EOF), take_until runs to end-of-input and FAILS before the try_map emits the var-anchored custom message, so the user gets a generic "found end of input, expected brace" at EOF instead of a VAR-anchored message. This is a NARROW diagnostic-quality REGRESSION vs the pre-TASK-0434 code (which anchored at VAR on truncated input because there was no brace to out-reach the ident reject). NOT a crash; correctness UNAFFECTED (the reserved VAR is still rejected, never reaches AST/codegen, in both old and new code). Verified against chumsky 0.9.3 TakeUntil::parse_inner (returns Err at EOF before the mapped closure runs). FIX options: take_until(just(brace).or(end())) then emit at var_span; or a bespoke commit-after-for parser that emits the var error without requiring a brace. Add a negative test for the brace-less case asserting VAR-anchored (line,col). LOW priority — malformed-input diagnostic quality only; caveat documented in for_loop_var() docstring + docs/grammar-algo.md note-4.
