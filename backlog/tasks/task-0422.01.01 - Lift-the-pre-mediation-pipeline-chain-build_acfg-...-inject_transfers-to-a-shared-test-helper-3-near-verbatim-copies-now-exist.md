If a new pass is inserted before inject_transfers, all three must update in lockstep or the sweeps silently diverge (a schedule could pass one sweep while the other no longer exercises the same lowering). DRIFT RISK, not a current defect. SCOPE: extract the chain into a shared test-only helper. CONSTRAINT: it must be reachable from BOTH nucleus-compiler/tests AND driver/tests without creating a dev-dependency cycle (backend-common depends on nucleus-compiler). Options to weigh: (a) a pub-but-#[doc(hidden)] or cfg(feature=test-helpers) fn in nucleus-compiler exposing the chain; (b) a tiny shared dev-only crate; (c) accept the duplication and add a cross-reference comment + a guard test asserting the two chains stay identical. Pick the least-invasive that removes the silent-divergence risk. Pointer: the chain is the DRIVER's source of truth (driver/src/main.rs pre-mediation section).
