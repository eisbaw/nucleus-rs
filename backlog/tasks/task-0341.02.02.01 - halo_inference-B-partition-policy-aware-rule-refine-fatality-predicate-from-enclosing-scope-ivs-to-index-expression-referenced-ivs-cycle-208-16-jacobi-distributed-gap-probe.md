## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
=== Filed as TASK-0341.02.02 AC#3 honest-BLOCKED follow-up, cycle 208 ===

Cycle 208 attempted 16-jacobi/distributed × pthreads-sync (partition=rows on the spatial y-loop, sync transfers — capability-compatible). The compiler rejects with:

```
halo-inference error (under partitioned iv): kernel call `jacobi5_or_seed` reads `field` at axis 0 with a non-affine index expression. Halo inference accepts only `iv + b` (b constant) — see PRD §13 / TASK-0260 module docs.
```

## Root cause

`apply_halo_inference_partition_aware` in `nucleus/nucleus-compiler/src/passes/halo_inference.rs:471-484` decides per-error fatality with:

```rust
if scope.iter().any(|iv| iv_is_partitioned(linked, iv)) {
    return Err(err);
}
```

`scope` is the FULL enclosing iter-var nest at the error site — `[t, y, x]` for the failing read inside `for t { for y { for x { jacobi5_or_seed(...) } } }`. `y` is partitioned ⇒ the predicate fires fatal.

But the failing index expression `(t + ITERS) % (ITERS + 1)` is at axis 0 of `field`, references only iv `t`, and `t` is NOT partitioned. The non-affine wrap on the time axis is harmless under spatial partition — no halo strip is needed on a non-partitioned axis. The (B) rule is over-conservative.

## Why the cycle-95 rationale (TASK-0275) predates this case

The cycle-95 comment justifies the (B) rule by citing 11-game-of-life: `grid[(t + ITERS) % (ITERS + 1)]` would newly-reject under a naive strict promotion. But 11-game-of-life uses pipelined.sched.nuc (no partition); no iv in scope is partitioned -> advisory; preserved. The (B) rule's coarse 'any-iv-in-scope-partitioned' predicate happens to work for that example because there is NO partition at all. The 16-jacobi/distributed case is the first encountered shape where a non-affine index on a non-partitioned axis SHARES the enclosing scope with a partitioned iv on a DIFFERENT axis.

## Proposed refinement

Record (or compute on demand) the set of ivs referenced by the failing index expression -- call it ivs_used_in_index. The fatality predicate becomes:

    // Refined (B'): only the ivs the failing INDEX EXPRESSION references
    // determine fatality, not the full enclosing scope.
    if ivs_used_in_index.iter().any(|iv| iv_is_partitioned(linked, iv)) {
        return Err(err);
    }

Edge case: ivs_used_in_index empty (purely-constant index that nonetheless failed const-fold) -> preserve current advisory behaviour (no halo to emit; no risk).

The walker in classify_index already computes ivs_used via collect_iter_var_refs; the patch is:
1. Augment the four error variants (DataDependentStride, StridedAccessNotSupported, MultipleIterVarsInIndex, NonAffineIndex) with an ivs_referenced: Vec<String> payload OR
2. Pair the error with its iv set in the returned errors_with_scope triple (cleaner -- does not change the error variant API surface).

Option 2 is preferred. HaloErrorWithScope becomes (HaloInferenceError, Vec<String> /* enclosing scope */, Vec<String> /* ivs in the failing index */).

## Acceptance criteria

1. Refinement lands: apply_halo_inference_partition_aware uses ivs_used_in_index instead of scope for the fatality predicate. Walker plumbs the iv set through.
2. Regression pin: existing 11-game-of-life shape (no partition + Mod wrap) stays advisory; existing partitioned-iv-on-the-failing-axis shapes (e.g. a stride-2 strided read in a partitioned outer loop) stay fatal. Add negative unit tests at both edges.
3. 16-jacobi/distributed × pthreads-sync PASSES bit-identical against reference.bin. PROMOTE the e2e-matrix [[skip]] entry to [[required]] with cycle citation.
4. Cross-backend sibling promotion: open a sub-task for promoting to the other tier-1 backends once AC#1-3 land on pthreads-sync.

## Honest scope LIMITS

- This refinement only affects apply_halo_inference_partition_aware. The strict apply_halo_inference entry point (used by no current caller per the cycle-95 module docs) is unchanged.
- Multi-axis partition (partition=blocks2d over a 2D outer iv) is unaffected -- that scope still has a partitioned iv, and any failing index in such a scope is correctly fatal if it references the blocks2d outer iv on either axis.
- The MultipleIterVarsInIndex case has multiple ivs referenced; under the refinement, fatal if ANY of them is partitioned (else advisory). That is the natural extension.
