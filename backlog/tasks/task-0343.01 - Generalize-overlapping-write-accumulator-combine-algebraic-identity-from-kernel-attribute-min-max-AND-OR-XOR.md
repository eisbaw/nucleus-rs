## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0343 cycle 189 hardcoded sum (wrapping_add) as the overlapping-write fan-in combine identity. This works for 08-histogram's i32 accumulator. The general case (PRD §10.1 bit-determinism + future schedules with min/max accumulators) needs the kernel to declare its algebraic identity. Concretely: add an attribute like 'kernel bin_inc : ... pure combine=sum' (or infer from the body when possible) and consume in render_accumulate_assign instead of hardcoding wrapping_add.

Scope:
- Grammar: combine=<name> attribute on kernel decl.
- Algorithm-IR sidecar: per-kernel combine identity (sum/min/max/and/or/xor).
- backend-common::render_accumulate_assign: map identity to Rust op (wrapping_add / min / max / & / | / ^).
- Defensive: reject a fan-in classified as accumulate whose owning kernel has no combine attribute declared (today the sum-only carve-out forgives this — the user gets bit-correct sum because every shipped accumulator IS sum).

Cross-references:
- TASK-0343 (parent): the cycle-189 sum-only landing.
- backend-common/src/multi_worker_walker/wait.rs::accumulate_op_for_scalar (the hardcoded match arm).
- PRD §10.1 (bit-determinism invariant — informs which identities are safe per scalar type).
