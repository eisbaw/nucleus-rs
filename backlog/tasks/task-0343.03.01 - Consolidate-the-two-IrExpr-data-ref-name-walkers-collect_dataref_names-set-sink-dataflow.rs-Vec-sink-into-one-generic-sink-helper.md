## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0343.03 promoted link::pipeline's private collect_data_refs to the public nucleus_compiler::algo::collect_dataref_names (BTreeSet<String> sink) and made pipeline delegate to it. A SECOND, structurally-identical walker remains: link::dataflow's private collect_dataref_names with a Vec<String> sink (it must preserve source order + duplicates for the CopyEdge value-flow propagation, TASK-0347). The two are a silent-sibling pair (feedback-silent-sibling-defect): a future change to the DataRef/Call/Neg/BinOp recursion must be mirrored in both. Scope: parameterise ONE walker over a generic sink (e.g. a FnMut(&str) closure or a Sink trait) so both the set-collecting and ordered-Vec-collecting callers share the recursion. Out of scope for TASK-0343.03 because collapsing them there would change the dataflow link pass's behaviour (Vec order/dups) without a test for that pass's order-sensitivity. Cross-ref: nucleus-compiler/src/algo/ir.rs::collect_dataref_names docstring (Known remaining sibling section); nucleus-compiler/src/link/dataflow.rs:315.
