## Goal

Silent-sibling follow-up discovered during TASK-0044.08 (cycle 232).
The host-excluding-barrier oracle-hole family closed for openmp-rs
(TASK-0044.01.03), mp-tcp-poll (TASK-0044.02.02.01), and the two
reactor backends mp-tcp-event + mp-uds-event (TASK-0044.08). The
SEVENTH tier-1 backend, pthreads-async, has the SAME hole and was NOT
in TASK-0044.08's scope (which was the two reactor backends only).

## Evidence (cycle 232 sibling sweep)

pthreads-async/tests/multi_worker_codegen.rs covers ONLY
02-split-add/split, whose barriers all emit Arc::new(Barrier::new(2))
(host-INCLUDED). It has NO host-EXCLUDING-barrier coverage: no
Arc::new(Barrier::new(4)) over {w0,w1,w2,w3}, no 15-transpose,
no distributed-rows. So a barrier-participant off-by-one on the
host-excluding shape would slip the fast pthreads-async emit oracle
and only bite the slow e2e gate.

15-transpose/distributed-rows x pthreads-async IS [[required]]
(nuc-nucleus/e2e-matrix.toml line ~471). All 7 tier-1 backends are
required on this cell.

## Scope / shape

pthreads-async is SHARED-MEMORY (NOT mediated) — same situation as
openmp-rs, NOT the reactor backends. So the fix mirrors the openmp-rs
template (TASK-0044.01.03):
  nucleus/backends/openmp-rs/tests/multi_worker_emit.rs ::
  transpose_15_distributed_rows_openmp_equiv_pthreads_sync
i.e. lower 15-transpose/distributed-rows, assert the emit carries the
host-EXCLUDING Arc::new(Barrier::new(4)) over {w0,w1,w2,w3} directly
(NO mediation — pthreads-async uses std::sync::Barrier natively),
assert it ALSO carries the host-INCLUDED new(5), and (if a twin is
reachable) byte-equiv vs pthreads-sync. Do NOT use the reactor-backend
mediation pattern.

NOTE: pthreads-async currently has tests/multi_worker_codegen.rs (no
tests/multi_worker_emit.rs). Add the new test to the existing
multi_worker_codegen.rs file rather than creating a new file, OR
follow the openmp-rs file naming — implementer's call.

## Honest scope

~50-60 LoC of test, single backend. Pattern fully established by
TASK-0044.01.03. e2e remains the load-bearing bit-identicality oracle;
this is a faster-feedback emit-string pin.
