PART 2 split out of TASK-0048.08 (which delivered PART 1, the on_violation=count AtomicU32 + USART1 program-exit summary sink). Today both the on_violation=log per-violation lines AND the on_violation=count program-exit summary share the SAME USART1 the firmware streams its raw computed output bytes over (e.g. ex1 save_output). The captured stream interleaves ASCII diagnostic lines with raw output bytes — distinguishable by the 'check loop ' ASCII prefix, but a real deployment wants diagnostics on a SEPARATE physical channel: a 2nd UART (USART2/3), an RTT (Real-Time Transfer) channel, or an SWO (Serial Wire Output) trace pin. This is a deployment nicety and a larger change (new NucleusShim diagnostic-channel seam + Renode platform wiring + capture harness for the 2nd channel), deliberately out of scope for TASK-0048.08. Code anchors: skeleton.rs USART1_SHIM_SRC report_violation docstring (notes the interleave wart); render_bin_main count summary block (same wart); the renode-embedded-check / renode-embedded-check-count recipes grep the shared USART1 capture by ASCII prefix.
