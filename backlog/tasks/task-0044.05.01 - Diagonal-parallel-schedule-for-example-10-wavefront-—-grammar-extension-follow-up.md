## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0044.05 cycle 199 honest-scope follow-up. The naive schedule for example 10 (wavefront) ships with a single fire site (`out_cost <-- wavefront(in_cost)`) — the entire 2D recurrence lives in one pure Rust kernel because v2's no-conditionals + single-assignment rules forbid the in-array carried recurrence at the algorithm level (same limit as TASK-0179 in-array prefix scan).

Consequently the algorithm has NO decomposition axis the schedule sublanguage can attach a `partition=` or `pipeline=` directive to — only the naive schedule is shippable today.

The anti-diagonal-parallel schedule (cells on diagonal i+j == k execute in parallel; diagonals execute sequentially) requires EITHER:

(a) Grammar extensions for in-array carries at the algorithm level (TASK-0179 already filed for the 1D prefix-scan case — diagonal LU is the 2D generalisation), OR

(b) A multi-pass diagonal-indexed encoding where each diagonal k is its own data symbol `diag_k : i32[H_PER_DIAG_K]`. This requires either H+W-1 hardcoded statements (awkward) OR loop bounds dependent on a loop variable like `for k : 0..K { for i : i_start(k)..i_end(k) {...} }` — which is rejected by the const-loop-bound rule (the ACFG builder only `eval_const`s bounds).

This follow-up tracks the work to lift one of these constraints so example 10 can express its parallel schedule at the algorithm/schedule level. Status: LOW priority, deferred-not-cancelled. Related: TASK-0179 (1D prefix scan), TASK-0103 (const-flow in Rust generics).
