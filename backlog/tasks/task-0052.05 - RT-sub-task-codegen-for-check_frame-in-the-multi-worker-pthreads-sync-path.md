## Description

TASK-0052.02 implemented check_frame codegen on the single-worker pthreads-sync emit path (nucleus/backends/pthreads-sync/src/lib.rs render_event Event::Loop arm). The multi-worker pthreads-sync emit path (nucleus/backends/pthreads-sync/src/multi_worker.rs) currently rejects check_frame with a typed ContractGap error (fail-loud) - no tier-1 cell exercises this combination. When a schedule attaches check loop V to a multi-worker (partition=workers) loop, the projection populates check_frame on every worker's outer Event::Loop and the multi-worker emit refuses. Wire the codegen so each thread runs Instant::now per iter + comparison + panic, mirroring the single-worker emit.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Wire check_frame codegen into multi_worker.rs Event::Loop arm.

Design:
- File-scope: collect Count check_frames from ALL workers' events, DEDUPE by sanitized ident (multi-worker projection duplicates the same frame across N workers for partition=workers). Emit ONE shared static AtomicU64 + ONE Drop-guard struct.
- fn main() early (before slot/barrier allocation): emit ONE Drop guard local per unique ident. Drop fires after handles.join() (host-thread end-of-scope).
- Per-worker Event::Loop arm: when check_frame.is_some(), wrap body in let _check_start = Instant::now() + body + let _check_elapsed = ...as_nanos() + on_violation dispatch. Reuse single-worker emit string verbatim.
- Multi-threading semantics:
  * Panic: each worker thread panics independently; join().expect propagates a panic to fn main (exit 101).
  * Log: per-thread eprintln, atomic per call; interleave between threads is acceptable (stderr-only, cross-backend differential is stdout).
  * Count: SHARED file-scope static, all threads fetch_add(Relaxed); Drop on host thread aggregates after all joins.
- Document the SHARED-across-threads Count semantic in code comments (avoid the doc-lie class).

Implementation steps:
1. Add count-frames collection in multi_worker.rs Plan::emit (aggregate across all workers, dedup by ident).
2. Emit file-scope Drop-guard struct + statics BEFORE fn main signature.
3. Emit guard locals after fn main {.
4. Replace the check_frame.is_some() reject with codegen mirroring single-worker render_event Event::Loop arm.
5. Add test: pthreads_sync multi_worker check_loop_panic emits Instant::now() + panic message per worker; compile-and-run negative proves panic exit 101.
6. AC#2: re-run e2e + determinism gates to confirm no regression.

### Honest limits / gotchas
- The generated Cargo.toml sets [profile.release] panic = 'abort'. Under panic=abort a worker thread panic SIGABRTs the WHOLE process (signal-terminated; exit status code is None), NOT exit 101. The test asserts the binary does NOT exit cleanly + the worker-panic message reaches stderr — both arms (SIGABRT vs exit 101) constitute valid evidence the dispatch fired. Documented in the test docstring.
- Did NOT add separate Log + Count multi-worker variants — brief calls out Panic singular. The single-worker test suite already pins the Log + Count emit strings; the multi-worker emit reuses the SAME helper functions (collect_count_check_frames / emit_count_reporter_struct / sanitize_loop_var / the per-iteration dispatch), so a Log or Count multi-worker schedule will use a verified-string-pinned codepath. If a tier-1 cell with multi-worker + Log/Count lands later, a string-pinning emit test should be added — filed as carry.
- Per-thread shared static: documented in multi_worker.rs Plan::emit comment that all worker threads fetch_add the same NUC_CHECK_COUNT_<ident> (PRD §6.3.5 tallied). Avoids the doc-lie recurring class.
