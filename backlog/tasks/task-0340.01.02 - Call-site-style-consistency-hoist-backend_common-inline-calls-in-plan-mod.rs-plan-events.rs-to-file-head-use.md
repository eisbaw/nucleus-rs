## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Cycle 179 slice 4 split mp-tcp-bufsync/lib.rs into 7 sub-modules but
introduced an internal stylistic inconsistency:

- `plan/worker_program.rs` imports `emit_count_static`,
  `emit_count_reporter_struct`, `emit_count_guard_local` from
  `backend_common::check_frame` at file head via `use`.
- `plan/events.rs::render_events` calls
  `backend_common::check_frame::emit_log_branch(...)` and
  `backend_common::check_frame::emit_count_branch(...)` inline (full path).
- `plan/mod.rs::build` calls
  `backend_common::multi_worker_walker::collect_pair_tiles(...)` inline.

The inline full-path form is correct Rust but mixes with the file-head
`use` form in sibling files. Future readers will assume the inline
form signals "imported elsewhere" — it does not.

## Acceptance criteria

1. Hoist the 3 inline `backend_common::*` call sites to file-head
   `use` statements:
   - `plan/mod.rs`: add `use backend_common::multi_worker_walker::collect_pair_tiles;`
   - `plan/events.rs`: add
     `use backend_common::check_frame::{emit_log_branch, emit_count_branch};`
2. Replace the inline full-path calls with bare names.
3. Verify `just build && just clippy` (must stay 0 warnings) and
   `just e2e` (must stay 112/102/0/10/0 bit-identical — pure
   re-shuffling of the symbol path; no behaviour change).
4. Commit message must explicitly disclose the no-behaviour-change
   claim with the empirical e2e cite (per slice-4 disclosure-honesty
   lesson on TASK-0340 notes).
