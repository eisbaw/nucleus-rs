## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
FOLLOW-UP from TASK-0048.12 (commit 6dc72dc), referenced in that task's AC#3 notes and in a code comment in nucleus/backends/embedded-pattern/src/skeleton/bin.rs (dma_push docstring, "fully zero-copy real-DMA path would require codegen to place the output array directly in a DMA-reachable region"). TASK-0048.12 made dma_push a REAL DMA1 MemoryToPeripheral USART1 TX, but the DMA *source* is a dedicated AXI-SRAM staging static (DMA_TX_STAGING @ 0x2404_0000) that dma_push CPU-copies the computed output into FIRST, because codegen places the actual output array in DTCM (RAM @ 0x2000_0000) which real STM32H7 DMA1/DMA2 cannot reach. The stage-copy is an HONEST bridge (disclosed in .12), not a silicon-faithful zero-copy DMA. This task would make the output array codegen place its buffer directly in an AXI-SRAM-resident region so dma_push can point M0AR straight at it with no CPU copy. SCOPE: this is a larger codegen/linker change than .12 (the output array is currently a `[T;N]` STACK local in the lowered `run`; it would need to become a `#[link_section=".axisram_tx"]`-style static, or the whole compute output region relocated, with the load/save lowering updated to match). LINKER PATTERN already proven in .12: per-region NOLOAD statics must be `INSERT AFTER .uninit` (NOT .bss — see .12 gotcha #1, which faults). NOTE: under Renode this yields NO additional verifiable fidelity (Renode models DTCM as DMA-reachable, fires synchronously on EN), so like .12 it is a pure HW-faithfulness upgrade, LOW priority, NOT an M10 blocker.
