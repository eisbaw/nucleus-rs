## Goal

Land the multi-worker arm of openmp-rs: a rayon-scope (or rayon::join / par_iter) per-worker substrate with a barrier-style rendezvous mechanism replacing pthreads-sync's std::thread + Condvar. Capability surface unchanged (sync + shared-memory + barrier/blocking) so every multi-worker schedule that pthreads-sync handles MUST emit bit-identical output under openmp-rs.

This unblocks all multi-worker [[skip]] cells filed in TASK-0044.01 cycle 191:
- 02-split-add/split, 03-reduction/distributed, 06-separable-filter/distributed + distributed2, 07-matmul/distributed + distributed-2d, 08-histogram/distributed, 13-cnn-inference/batch_parallel

Each promotes to [[required]] once bit-identical is verified.

## Closest template

The same template TASK-0044.01 cycle 191 used for single-worker — pthreads-sync — but the multi-worker arm now: `pthreads-sync/src/multi_worker.rs` (684 LoC). The diff is the runtime substrate:

- pthreads-sync: `std::thread::spawn` + `std::sync::Condvar` for per-(DataId,SeqTag) rendezvous slots.
- openmp-rs: rayon `scope` (or `join` / `par_iter`) for the worker substrate; barrier-style rendezvous (rayon's implicit join at scope-end or a shared `std::sync::Barrier`).

Check whether `backend_common::multi_worker_walker`'s rendezvous_prefix mechanism extends to rayon, or whether a new arm is needed. Per project memory `project-backend-common-crate`, the lift surface is the single source of truth; do NOT fork the walker.

A future regression of THAT pub shim wouldn't be caught by the byte-identical test because byte-identical compares against pthreads-sync's MULTI-worker output — both could drift in lockstep. The independent fixture test bites loud.
