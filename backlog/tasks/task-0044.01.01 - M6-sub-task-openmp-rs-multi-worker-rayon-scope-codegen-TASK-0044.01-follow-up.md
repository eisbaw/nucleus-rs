## Goal

Land the multi-worker arm of openmp-rs: a rayon-scope (or rayon::join / par_iter) per-worker substrate with a barrier-style rendezvous mechanism replacing pthreads-sync's std::thread + Condvar. Capability surface unchanged (sync + shared-memory + barrier/blocking) so every multi-worker schedule that pthreads-sync handles MUST emit bit-identical output under openmp-rs.

This unblocks all multi-worker [[skip]] cells filed in TASK-0044.01 cycle 191:
- 02-split-add/split, 03-reduction/distributed, 06-separable-filter/distributed + distributed2, 07-matmul/distributed + distributed-2d, 08-histogram/distributed, 13-cnn-inference/batch_parallel

Each promotes to [[required]] once bit-identical is verified.

## Closest template

The same template TASK-0044.01 cycle 191 used for single-worker — pthreads-sync — but the multi-worker arm now: `pthreads-sync/src/multi_worker.rs` (684 LoC). The diff is the runtime substrate:

- pthreads-sync: `std::thread::spawn` + `std::sync::Condvar` for per-(DataId,SeqTag) rendezvous slots.
- openmp-rs: rayon `scope` (or `join` / `par_iter`) for the worker substrate; barrier-style rendezvous (rayon's implicit join at scope-end or a shared `std::sync::Barrier`).

Check whether `backend_common::multi_worker_walker`'s rendezvous_prefix mechanism extends to rayon, or whether a new arm is needed. Per project memory `project-backend-common-crate`, the lift surface is the single source of truth; do NOT fork the walker.

## Forward-carried lessons from TASK-0044.02.02 cycle 195 (mp-tcp-poll multi-worker)

When implementing openmp-rs multi-worker codegen, note:

1. **lower_for_test does NOT apply host_mediation_inject**. If your test fixture has a host-excluding barrier (e.g. 03-reduction/distributed places all work on w0..w3 with NO host), the backend's defensive ContractGap fires at `Plan::build` time. Fix: either route through the driver in the test, or apply `apply_host_mediation_inject` inline AFTER `inject_syncs` + `inject_transfers` and BEFORE `acfg_to_events`. See poll's `tests/multi_worker_emit.rs::separable_filter_06_distributed2_poll_equiv_bufsync` for the manual-pass-sequence template (mirrors bufsync's `tests/host_relay_emit.rs`).

2. **host_mediation_inject docstring driver gate enumeration**. When openmp-rs lands multi-worker, audit whether it needs this pass too — openmp-rs uses shared-memory barriers (std::sync::Barrier on Arc) so it likely does NOT need host mediation, but verify and update the docstring enumeration in lockstep.

3. **Sibling-of-bufsync emit-string oracle test pattern** is high-value: take the same input, emit through both your backend AND a 'twin' (here mp-tcp-bufsync) that should produce the same shape modulo a known swap-set, and assert canonicalised equality. Catches silent-sibling regressions of the swap before they hit `cargo build`. See poll's `tests/multi_worker_emit.rs` for the canonicalisation pattern (4 legal differences: wait-primitive call swap × 3 + apply_nonblocking line + module-doc/banner text).
