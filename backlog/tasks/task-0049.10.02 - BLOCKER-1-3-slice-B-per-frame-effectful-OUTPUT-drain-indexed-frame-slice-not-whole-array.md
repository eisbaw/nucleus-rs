## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Slice B of TASK-0049.10 (per the parent's A/B/C/D order; follows slice A = TASK-0049.10.01 DONE). The embedded backend's render_fire None arm (effectful OUTPUT / save) currently drains the WHOLE array each frame: first_data_input returns the BARE array name (data_name(slice.data), ignoring slice.indices) and the drain is sized core::mem::size_of_val(&spk_out) = the whole array. But ex14 fires fe_emit(spk_out[frame]) and rf_transmit(bt_out[frame]) — the effect input is an INDEXED one-frame slice, fired once PER frame inside the for-frame loop. Draining the whole array every frame is wrong (N_FRAMES x over-drain + wrong bytes vs reference.bin layout).

FIX (additive, mirrors slice A): in the None arm, when the effect's data input slice has NON-EMPTY indices, drain the indexed frame place via the slice-A structural helper backend_common::render::render_indexed_place(slice, ctx) -> spk_out[start..start + 16usize], sized by size_of_val(&place) (the row). When the input slice has EMPTY indices (the tier-1 whole-array save_output(c) shape), keep the BARE name + whole-array drain BYTE-IDENTICALLY. Both .as_ptr() and size_of_val work on a [T] sub-array place exactly as on a [T;N] array, so the dma_push/dma_wait shape is otherwise unchanged.

SCOPE: OUTPUT drain only. INPUT lowering was slice A. Per-worker input partition + multi-output .resc capture ordering is slice C. renode-multimcu recipe resolution + byte-exact gate is slice D. Do NOT claim renode byte-exact in slice B (needs C+D).

REGRESSION GUARD (load-bearing): the whole-array save path (empty-indices input) backs 7 M6 cells + M10 ex1/5/9 + 02-split-add. The indexed-drain branch must be PURELY ADDITIVE — only the indexed-input effectful-save shape (which no shipped/e2e-live cell exercises; all 7 embedded_multimcu cells are [[skip]]) changes. e2e MUST stay 427/364/0/63/0 byte-for-byte.
