## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Architect review of TASK-0049.10.02 (P3-1; shared latent with slice A). backend_common::render::render_indexed_place returns SliceForm::Scalar (D[idx], a single T) when a DataSlice is FULL-RANK indexed. The embedded backend's per-frame effectful arms then emit D[idx].as_ptr() (drain, render.rs effect_drain_place ~640) / D[idx].as_mut_ptr() (fill, render.rs slice-A input arm ~544) — neither compiles on a scalar T (no as_ptr/as_mut_ptr on i32).

Cannot occur for any CURRENT shape: ex14 spk_out/bt_out/mic_in/bt_in are i32[N_FRAMES][SAMPLES_PER_FRAME], so an [frame] index is partial-rank => always SliceForm::SubArray (a [T] slice, valid). But a future effectful kernel with a FULL-RANK-indexed scalar input/output (e.g. 1-D data x:i32[N], emit(x[i])) would emit non-compiling firmware — a latent panic-not-diagnostic / silent-broken-emit gap.

FIX (when picked up): make the per-frame effectful in/out arms reject (or correctly handle) a Scalar place with a typed EmitError::UnsupportedFeature carrying a precise message, instead of emitting code that fails the downstream cross-compile with an opaque rustc error. Likely needs render_indexed_place (or a sibling) to expose the SliceForm Scalar/SubArray distinction the arms currently lose through the String return. Touches BOTH the slice-A fill arm and the slice-B drain arm — own review. e2e-inert (no current cell hits it).
