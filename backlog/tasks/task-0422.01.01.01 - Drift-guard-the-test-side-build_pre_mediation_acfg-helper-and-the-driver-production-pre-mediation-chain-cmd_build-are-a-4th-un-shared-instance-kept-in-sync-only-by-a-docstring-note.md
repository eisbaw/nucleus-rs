Architect P3.2 (cycle-245, TASK-0422.01.01 review). TASK-0422.01.01 consolidated the 3 TEST copies of the pre-mediation pass chain into nucleus_compiler::test_support::build_pre_mediation_acfg. The helper docstring instructs keeping the two in sync, but nothing ENFORCES it — a new pass inserted before inject_transfers in the driver would not trip any gate if the helper is not updated, and the corpus sweeps (task0428 + task0422_01) would silently stop exercising the real lowering. This is precisely the feedback-silent-sibling-defect class. SCOPE/OPTIONS: (a) a guard test asserting the driver chain and the helper chain produce an identical ACFG for a sample (algo,sched) — but the driver chain is interleaved with backend-conditional logic + String error mapping, so extracting a comparable unit is the hard part; (b) factor the driver's pre-mediation sequence into a shared fn that BOTH cmd_build and the helper call (the real fix, larger — must preserve the driver's display_with_src error mapping which differs from the helper's {e:?}); (c) accept the docstring note as the guard and close as wont-fix. LOW priority — no current drift; this captures the risk in durable state per the silent-sibling memory rather than relying on a comment. KEY DESIGN DECISION: PreMediationError is deliberately NOT #[non_exhaustive]. A non_exhaustive enum forces the cross-crate driver match to carry a wildcard _ arm, which would SILENTLY catch a newly-added pass variant -> exactly the silent-sibling defect this task fights. Without non_exhaustive, adding a pass variant breaks the driver match at COMPILE time, forcing the implementer to assign the new pass a user-facing string. That compile error IS the drift-prevention guarantee.
