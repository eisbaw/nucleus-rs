## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0343.03 added check_accumulator_consistency (backend-common/src/multi_worker_walker/collect.rs) which classifies a data symbol as an algorithm-level accumulator iff its IrStmt::Dataflow LHS name appears among the RHS data references (LHS-appears-in-RHS). This does NOT recognise a TRANSITIVE accumulator, e.g. acc <-- f(tmp) where tmp <-- g(acc) earlier in the same scope. No shipped schedule needs this today. IMPORTANT failure-mode note: because the cross-check only ADDS a reject path, a transitive accumulator the LHS-in-RHS test misses would be a FALSE REJECT (fail-loud EmitError::AccumulatorShapeMismatch), NOT a silent miscompile -- so the safety property is preserved; this is purely a precision/usability gap. Scope: extend collect_accumulator_names to compute a transitive read-closure per scope (data symbol X is an accumulator if X transitively feeds its own update). Cross-ref: collect.rs::check_accumulator_consistency docstring (Scope LIMIT section).

## Implementation Notes

Forward-carried from TASK-0432 (cycle 247 architect P3a): the cumulative-array classifier (collect_cumulative_data_names, sidecar.rs) decides NON-cumulative vs cumulative purely on STRUCTURAL IrExpr equality of the self-read index vs the LHS index (IrExpr derives plain PartialEq/Eq, no span/aux). For the textbook distributed scatter histogram[bucket(input[i])] <-- inc(histogram[bucket(input[i])]) this correctly stays a non-cumulative wrapping_add accumulate BECAUSE both index sites are the identical Call{bucket,[input[i]]}. FRAGILITY to track when generalising the cross-check: any pass that rewrites only ONE of the two structurally-identical index occurrences (CSE, partial constant-fold, a non-idempotent index spelling) would make indices compare UNEQUAL -> classifier flips to cumulative -> the whole-array-replicate + host element-wise-sum combine becomes xN-wrong silently. Currently pinned only by the e2e byte-match (08-histogram/distributed.textbook + 19-histogram-unconstrained). A classifier-side regression note / guard belongs here if that surface widens.

Forward-carried from TASK-0343.01.01 review (architect P3.2): collect_combine_for_accumulators (sidecar/collectors.rs) only records a combine entry when the accumulator RHS is a DIRECT IrExpr::Call. A future BinOp-RHS accumulator (acc[i] <-- acc[i] + x[i]) is detected by the gate predicate but gets NO combine entry -> conservatively REJECTED (fail-loud, never silent-wrong). When generalizing the accumulator-detection predicate here, also widen the combine-entry collector to non-Call RHS shapes so they are not false-rejected.
