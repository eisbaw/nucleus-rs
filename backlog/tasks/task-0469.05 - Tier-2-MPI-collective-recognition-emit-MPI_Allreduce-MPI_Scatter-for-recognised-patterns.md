## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
HPC perf credibility. PRD section 7.2 deferred this deliberately: v2 emits correct point-to-point only, which is correct but suboptimal, and the thesis (ch7 tier-2, ch10) states the MPI backends emit point-to-point rather than collectives as a named residual. Recognise the distributed-reduction fan-in pattern (per-worker partials combined at a host under an associative-commutative combine — the same algebra combine=sum/or/xor/min/max/and rests on) and lower it to MPI_Allreduce/MPI_Reduce; recognise host-broadcast and host-scatter shapes and lower to MPI_Bcast/MPI_Scatter. Implement as a tier-2 peephole over the event lists (or a recognised-pattern marker from the existing reduction machinery), guarded so an unrecognised shape still falls back to correct point-to-point. Must preserve byte-identity against the same frozen reference under mpiexec; the fixed-order fold guarantee (0453.03 fsum) constrains which float combines may use a hardware collective whose order is not controlled — likely integer combines first, float only where the collective order is pinned or the combine is order-independent (min/max).
<!-- SECTION:DESCRIPTION:END -->
