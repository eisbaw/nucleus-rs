An indexed-output effectful kernel is structurally identical to a pure indexed compute, so render_fire lowers fe_capture to 'kernels::fe_capture()' = the verbatim-extracted STUB returning [0i32;16]. Firmware mic_in/bt_in = all zeros => output cannot match reference.bin (which is REAL: 466/512 non-zero bytes, generated by reference/ binary from real input.bin). FIX needs the effectful marker propagated algo-AST -> lower -> Event/FireBinding (or a sidecar table) -> embedded render_fire, which must lower an effectful indexed-output zero-input kernel to a PER-FRAME shim region-read (shim.alloc_in_region advancing its cursor once per frame into mic_in[frame*16..]) instead of a pure stub call. REGRESSION RISK: the structural effectful classification is load-bearing for 7 M6 cells + M10 ex1/5/9 + 02-split-add; changing it must not move them.

BLOCKER 2: per-worker INPUT partitioning. fe needs the mic_in slice of input.bin, rf needs the bt_in slice (input.bin = 512B = mic_in[256]++bt_in[256]). The generated multimcu.resc injects ONE $input; each loader-worker's shim cursor must read its OWN slice. Needs the .resc / shim to partition input per worker by symbol.

BLOCKER 3: multi-worker OUTPUT capture ordering. BOTH fe (fe_emit spk_out -> usart1) AND rf (rf_transmit bt_out -> usart1) drain to the SAME $uartFile (multimcu.resc: 'usart1 CreateFileBackend $uartFile true' on BOTH fe and rf). reference.bin (512B) = spk_out(256)++bt_out(256) in the reference generator's layout. The two USART1 streams concatenate by Renode write order; need deterministic ordering (barrier/boot-order) matching reference.bin layout, OR a single designated aggregator worker.

KEY CORRECTION to the cycle's stated plan: TASK-0049.02 (stateful kernels.rs with a call cursor) is the TIER-1 SINGLE-PROCESS path (kernels called directly, need shared cursor + Drop-flush) — it does NOT address the FIRMWARE blockers above (the firmware does NOT extract effectful kernels; it maps them to shim hooks).
