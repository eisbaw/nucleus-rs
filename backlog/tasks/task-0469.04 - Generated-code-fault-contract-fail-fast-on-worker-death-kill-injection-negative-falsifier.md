## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A compiler is production-ready when its OUTPUT is. The soundness gate proves no deadlock UNDER THE MODEL (all workers alive, the static firing order honoured); it says nothing about partial failure. A production user asks within the first hour: what happens when a worker process dies mid-run? Hand-written socket code typically hangs. Define and implement an explicit contract for the multi-process backends (mp-tcp-*, mp-uds-event): if any worker exits non-zero or its connection drops, every other worker fails fast with a named-peer diagnostic and a non-zero exit within a bounded time, rather than blocking forever on a recv. Then prove it bites with a kill-injection negative falsifier in the spirit of the existing falsifier discipline (a peer is killed mid-run; the test fails unless the survivors exit non-zero within the bound and name the dead peer). Sibling-aware of TASK-0461.01 (unbounded accept) and TASK-0461 (connect/accept-phase stall) — those are connect-phase; this is steady-state death. Scope note: this is a liveness-under-failure contract on generated code, NOT a change to the static-firing model or the gate.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
