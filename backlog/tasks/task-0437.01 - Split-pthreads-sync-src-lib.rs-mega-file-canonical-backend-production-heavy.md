pthreads-sync/src/lib.rs is ~1044 LoC and production-heavy: unlike block_transform.rs (split in TASK-0437 by a mechanical inline-test carve-out), this file has NO inline test mod to extract. Its bulk is emit / render_main_rs / render_array_init / render_events_in PLUS the PUBLIC render_single_worker_main* API that five sibling backends depend on (pthreads-async / mp-tcp-bufsync / openmp-rs / mp-tcp-poll / mp-uds-event). Splitting therefore requires moving PRODUCTION fns into cohesive sub-modules along the module-doc Event:: arm seams (Fire / Loop / Sync-Push-Wait, per the docstring) while PRESERVING the public API EXACTLY (re-export the render_single_worker_main* surface from lib.rs so downstream `use backend_common::... / pthreads_sync::...` paths keep resolving). This is a distinct risky-refactor boundary from the block_transform carve-out (phase3 anti-pattern: never batch across a risky refactor boundary), hence deferred to its own cycle. The allow-list entry for nucleus/backends/pthreads-sync/src/lib.rs in justfile:check-mega-files STAYS until this lands; remove it (direction-B guard) only after the split drops the file under 1000 LoC. Gotchas carried forward from TASK-0437: (1) edition-2021 foo.rs + foo/ dir coexistence works (block_transform.rs stayed the module file, tests.rs went under passes/block_transform/); for a production split prefer either lib.rs as the module file + sub-files under a pthreads_sync_emit/ dir OR named sibling modules declared from lib.rs. (2) `use super::*` resolves to the parent module after a move. (3) the direction-B allow-list removal is MANDATORY and is checked by `just ci` (not by the cheap pre-commit subset). (4) clippy re-lints moved code — watch doc_lazy_continuation on any /// you touch and needless_borrow.
