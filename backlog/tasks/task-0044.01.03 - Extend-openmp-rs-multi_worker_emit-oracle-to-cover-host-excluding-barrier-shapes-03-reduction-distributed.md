## Goal

The cycle-196 openmp-rs multi_worker_emit oracle (tests/multi_worker_emit.rs) covers 02-split-add/split and 06-separable-filter/distributed2. Neither exercises the host-excluding-barrier shape (workers={w0,w1,w2,w3} without host) that exercises a different barrier-participant-count path (Arc<Barrier>::new(N-1) excluding host).

03-reduction/distributed IS a promoted [[required]] cell so the e2e gate verifies bit-identicality bit-for-bit. But the cheaper/faster emit-string oracle has a coverage hole on the host-excluding-barrier shape — a regression that produced a runtime-correct but structurally-different Arc<Barrier>::new(N) (off-by-one) would slip past the oracle and only bite e2e.

## Scope

Add a 3rd test (`reduction_03_distributed_openmp_equiv_pthreads_sync`) in tests/multi_worker_emit.rs that:

1. Lowers 03-reduction/distributed via test_common::lower_for_test (no inline pass sequence needed — openmp-rs is shared-memory; host-excluding barriers lower via Arc<Barrier>::new(N) directly, no host_mediation_inject pass).
2. Asserts byte-identicality (after the cycle-196 rayon canonicalisation) of openmp-rs vs pthreads-sync main.rs.

## Implementation Plan + EMPIRICAL FINDING (premise correction)

EMPIRICAL FINDING (verified by throwaway probe tests, since reverted):
The task premise that 03-reduction/distributed exhibits a host-EXCLUDING
barrier is FALSE. Both via lower_for_test (apply_partition_workers=true)
AND via the full driver pipeline, 03-reduction/distributed emits exactly
2 barriers, BOTH with participants {host,w0,w1,w2,w3} = Arc::new(Barrier::new(5)).
Host is INCLUDED. Reason: inject_syncs builds barrier participants from
the union of cross-worker transfer/write boundaries; host owns load_input
(produces a, transferred to workers) and combine (consumes partials from
workers), so every phase-boundary barrier includes host. The accumulate
placement on {w0..w3} does NOT yield a host-excluding barrier. The shipped
e2e-matrix.toml itself documents (near the 13-batch_parallel block) that
this example family has NO host-excluding barrier.

So AC#2 as written (assert new(4) not new(5)) is UNSATISFIABLE on
03-reduction/distributed.

A scan of ALL multi-worker schedules found the genuinely host-excluding
shapes are: 09-producer-consumer/pipelined, 13-cnn/pipeline_parallel,
16-jacobi/distributed, 15-transpose/distributed-rows. Of these, ONLY
15-transpose/distributed-rows is BOTH (a) genuinely host-excluding AND
(b) a promoted [[required]] cell on openmp-rs (and all 7 tier-1 backends).
16-jacobi/distributed is host-excluding but [[skip]] everywhere;
09 and 13 are host-excluding but [[skip]] on openmp-rs (capability-gated).

RETARGET DECISION: target 15-transpose/distributed-rows instead of
03-reduction/distributed. This is the cell that actually exhibits the
coverage hole the task exists to close (host-excluding barrier) AND is a
required cell on openmp-rs. Verified emit (openmp-rs == pthreads-sync
byte-identical) carries FOUR barriers: bar_0/1/3 = new(5) host-included
AND bar_2 = Arc::new(Barrier::new(4)) participants {w0,w1,w2,w3} host-
excluding. So the cell exercises BOTH shapes (stronger than the original
single-shape intent).

PLAN:
1. Add reduction-style 3rd test reduction_15_transpose_distributed_rows_
   openmp_equiv_pthreads_sync (named for the real example) in
   backends/openmp-rs/tests/multi_worker_emit.rs, mirroring
   split_02_openmp_equiv_pthreads_sync but lowering 15-transpose/
   distributed-rows via lower_for_test with apply_partition_workers=true.
2. Assert openmp-rs main.rs == pthreads-sync main.rs after rayon
   canonicalisation (assert_openmp_main_equiv_sync).
3. AC#2 (host-excluding pin): assert main.rs contains
   Arc::new(Barrier::new(4)) AND the participant comment {w0,w1,w2,w3},
   plus that a host-INCLUDED new(5) ALSO appears (both shapes).
4. Run full gate; confirm test count +1 (this file), e2e unchanged.

Note: the test name keeps a "reduction_"-free, example-accurate name to
avoid a comment/doc lie (it is NOT 03-reduction).
