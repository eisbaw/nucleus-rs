## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The embedded-pattern capability matrix caps at sync / buffer=1 / blocking (thesis tab:capabilities), so the headline contribution — IO semantics as swappable schedule directives — is unrealized on the tier that motivated it (the 2013 ISP-firmware double-buffered DMA pipelines). Async double-buffering matters MOST on bare metal, where there is no OS to absorb latency.

Work: extend embedded-pattern + the shim trait to advertise and honor async, buffer=2 (DMA descriptor ring), notify=event (IRQ completion): a Push becomes a DMA descriptor enqueue with completion tracked by IRQ; a Wait becomes an IRQ-driven completion; pipeline=D initial markings honored on the embedded path. Validate in Renode on both committed shim families where the simulator model supports it (STM32H7 USART+DMA; nRF52840 UARTE EasyDMA), byte-exact against the same frozen references.

Capability-resolution both ways: a newly-accepted async schedule must actually run; a still-unsupported demand must still be rejected loudly naming the missing capability.

References: TASK-0048.13 (zero-copy DMA placement — complementary, not subsumed), 22-dma-pio-demo (per-edge mode=dma|pio hints), TASK-0048.11 (Renode DMA-USART de-risk spike, Done), staged boot-order machinery (TASK-0049.05.03). Renode env is NOT blocked here (memory: project-renode-env-not-blocked).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Cross-links from the architecture review (2026-06-10): depends on TASK-0455.08 (XferFacts) because notify currently has NO sidecar surface at all — threading IRQ-event notify per-seq is the first real consumer. Two findings to absorb at design time: (1) the DMA arm today is a modelled arm+spin, explicitly synchronous (embedded-pattern render.rs ~390-421); buffer=2 needs split-phase emit (arm i+1 while i in flight) that the atomic Push event cannot express — expect the renderer to carry it as software pipelining within the loop body, not a new event variant. (2) Decide the Region story here: Alloc/Free events + Region are dead contract surface (never emitted, petri_to_events.rs:113-121; all 10 capabilities declare memory_regions=[heap] only; place_data parsed+capability-checked then discarded, capabilities.rs:432-439). Embedded TCM/SRAM placement is the first real consumer — choose Alloc-events vs sidecar lowering, or delete the variants (opacity-gate-rot discipline).

DESIGN DECISIONS (cycle, TASK-0455.02):
REGION STORY (finding 2): KEEP Event::Alloc/Free variants, do NOT delete. Rationale: place_data lowering + Alloc/Free emission + the Region type all live in nucleus-compiler (event.rs, passes/, capabilities.rs) = OUTSIDE embedded-pattern ownership (other agent / frozen). The embedded backend cannot be the consumer that flips them live without compiler-pass work. The embedded Alloc/Free render arm stays a fail-loud reject (render.rs ~508). memory_regions stays [heap]. TCM/SRAM placement = compiler honest-defer (a real follow-up needs a place_data->Alloc-event lowering pass in the compiler). This is the opacity-gate-rot-honest call: the variant is NOT yet redundant (no machinery subsumes it), so leaving it as a guarded reject is correct; deleting it would be the WRONG call because the compiler still owns the place_data surface that would feed it.
EMPIRICAL EVENT SHAPE (verified by emit): a loop-carried cross-worker transfer (09 produce/transform) on the embedded multi-MCU path lowers the stream Push/Wait INSIDE the for-n loop body, bracketed by per-iteration irq_barrier(1)/irq_barrier(2) from the (frozen) walker. Those per-iteration barriers serialize producer<->consumer, so genuine TEMPORAL DMA overlap is not achievable in this shape (and the modelled Renode DMA completes synchronously anyway). OBSERVABILITY is therefore the descriptor-RING-OCCUPANCY-reaching-2 reading of AC#4 (state property), NOT a temporal trace: the shim holds a depth-2 ring; the renderer emits split-phase ring_arm + notify-selected completion wait; occupancy high-water = 2 proven structurally (unit test) + the byte-exact Renode run proves value-correctness. Observability must NOT pollute the data UART (would break reference.bin byte-exactness), so it is a source-structural + ring-state property, not a UART print.

New shim trait DEFAULT method dma_link_irq_wait (delegates to poll-spin under modelled sync DMA; both families inherit, zero per-family churn). 3 skeletons (lib/bin/multimcu) emit ring statics + static_mut_refs allow.
