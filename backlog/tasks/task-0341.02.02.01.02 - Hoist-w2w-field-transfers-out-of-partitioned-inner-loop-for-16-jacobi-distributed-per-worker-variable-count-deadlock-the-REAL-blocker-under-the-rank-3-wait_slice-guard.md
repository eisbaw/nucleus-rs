## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
ROOT CAUSE (empirically reproduced cycle 211b/this cycle, pthreads-sync):

Built 16-jacobi/distributed x pthreads-sync with the rank-3 wait_slice guard temporarily lifted (guard returned Ok(None) for the rank-3 whole-array tile). The single rank-3 tile constructed for field=DataId(0) is the WHOLE-ARRAY case: bounds=[(t,0..5),(y,0..8),(x,0..8)] vs dims=[5,8,8] (all axes full). It collapses cleanly to the whole-array accumulate arm. Codegen then COMPLETES (no compile error). But the emitted binary DEADLOCKS (timeout 124, no output.bin).

The deadlock is upstream of wait_slice, in transfer_inject xfer PLACEMENT:

  for t in 0..5 {
    bar_1.wait();
    for y in <band> { for x in 1..7 {
      { _tmp = wX_slot.wait(); field accumulate }  // recv from EACH peer
      field[...] = jacobi5_or_seed(...);
      wX_slot.push(field.clone());                 // send to EACH peer
    } }
    bar_2.wait();
  }

The w2w field Wait+Push are INSIDE the innermost for x loop, so the number of push/wait ops per worker = band_rows * 6 (x-span). Bands are unequal (floor-with-spillover, 6 rows / 4 workers):
  w0: y 1..3 (2 rows) -> 12 exchanges
  w1: y 3..5 (2 rows) -> 12
  w2: y 5..6 (1 row)  -> 6
  w3: y 6..7 (1 row)  -> 6
Slot is a single-element Mutex<Option<T>>+Condvar (push overwrites, no count). After w2 finishes its 6 iterations and reaches bar_2, w0 is still on iteration 7+ of 12, blocked forever on w0_slot_6.wait() (recv from w2) — w2 will never push again. DEADLOCK.

Barriers are NOT the bug: bar_2 is correctly a 4-party (workers-only) barrier and all 4 workers wait on it.

WHY wait_slice cannot fix this: the placement/frequency of the w2w transfers is decided in transfer_inject (shared compiler layer), BEFORE backend codegen. All 5 wait_slice-using backends inherit the identical broken event structure. No wait_slice change (N-D dispatch or otherwise) alters the loop nesting that causes the count mismatch.

SEMANTIC NOTE: even fixing the count mismatch requires hoisting the exchange to once-per-t (after all workers finish step t, before t+1) so the whole-array accumulate reassembles field[t] coherently. Per-(y,x) whole-array exchange is also a frequency bug, not just a count bug. This is the TASK-0126-class "ACFG-driven xfer placement" work.

RELATION TO TASK-0341.02.02.01.01 (the wait_slice task): that task is NOT the operative blocker. Its rank-3 guard is merely the FIRST error hit; lifting it reveals this deadlock. For 16-jacobi the only rank-3 tile is whole-array (Ok(None)), so the banded N-D nested-loop path is never exercised. Landing a speculative N-D wait_slice extension would add untested codegen surface that promotes ZERO cells. Left TASK-0341.02.02.01.01 In Progress / honest-BLOCKED on THIS task.

RELATION TO TASK-0330 / TASK-0329.01: same in-Loop-w2w-Push family that already blocks mp-tcp-bufsync/poll on this very example, but here it manifests as a runtime deadlock (5 wait_slice backends) rather than a defensive compile guard (bufsync/poll host-relay collector).
