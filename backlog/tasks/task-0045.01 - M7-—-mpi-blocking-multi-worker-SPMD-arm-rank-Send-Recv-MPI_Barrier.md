## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
GOTCHAS / LESSONS (forward-carried where they bear on TASK-0045.02/0046):

1. TAG=rid is load-bearing, not cosmetic. A worker with multiple concurrent transfers to/from the SAME peer (03-reduction: host scatters a to 4 ranks + gathers partials from 4 = 8 transfers) cross-matches by MPI send-order WITHOUT distinct tags. mpiexec -n N (all ranks live) exposes it; -n 1 hides it. The rendezvous id (per (DataId,SeqTag) pair) IS the tag.

2. WALKER REUSE works via an emitted rendezvous PRELUDE (VecChan/ScalarChan/WorldBar) whose .push()/.wait() the shared render_worker_events targets (rendezvous_prefix=mpi, prefix=""). prefix="" is correct for SPMD (each match-rank arm is its own scope, no closure-capture clones like pthreads w0_). Fire/Loop/gather-slice-paste arithmetic stays byte-shared with in-process backends — confirmed by 03-reduction emitting the exact slice-paste gather the walker produces.

3. STANDARD-MODE MPI_Send may block above the eager limit; the schedule ordering targets the fully-async pthreads Slot model, so a large-message adversarial ordering could deadlock. Shipped examples (<=2KB) buffer eagerly. check-mpi wraps runs in `timeout` so a deadlock fails LOUD. Non-blocking/buffered send is M8 (TASK-0046).

4. CAPABILITY GATE is the gatekeeper: async/buffer/event schedules (05-stencil/distributed) are hard-rejected for sync-only mpi-blocking at driver check_schedule_compat. Do not confuse a rejected schedule with a backend bug.

5. WHOLE-WORLD barrier only: the participant-SET == all-used check is correct because mpiexec -n N launches exactly the used-worker count; equal per-rank CALL COUNTS rely on inject_syncs never emitting a barrier inside partition=workers scope (documented upstream dependency).

6. mpi_equivalence_scalar is a DEAD guard today (all ScalarType have rsmpi Equivalence incl bool) — kept as panic-not-diagnostic future-proofing, documented honestly so it is not mistaken for a live negative arm.
