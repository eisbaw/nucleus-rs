## Goal

Precursor of TASK-0044.02 (mp-tcp-poll backend). The mp-tcp-poll capability surface introduces `notify = ["poll", "barrier", "blocking"]` — `poll` is a NEW notify variant not currently in the schema. Without this precursor landing first, TASK-0044.02 hits a 'unknown notify variant' error mid-cycle on the capability-compat check.

## What to land

1. `nuc-nucleus/docs/capabilities-toml.md` (if it exists; create if not) — schema documentation lists `poll` as a valid notify variant alongside `barrier`, `blocking`, `event`.
2. Wherever the schema validator hard-codes the notify allow-list (likely `nucleus/nucleus-compiler/src/...capabilities...` — grep for the existing `barrier` / `blocking` / `event` matches), add `poll` to the same enum / match arms.
3. The capability-compat check (the one that rejects async/buffer/event schedules against sync-only backends) must treat `poll` analogously to `barrier`+`blocking` (both are sync-side wait primitives; neither satisfies an `event` requirement).
4. Unit test: add a capability fixture with `notify = ["poll"]`; assert it passes parse + compat-check on a schedule requiring sync notify; assert it FAILS compat-check on a schedule requiring `event` notify.

## Acceptance criteria

1. Schema doc + validator both recognise `notify = "poll"` as a valid variant.
2. Compat-check semantics: `poll` is sync-equivalent (rejects event-required schedules); does NOT silently accept event schedules.
3. New negative test added pinning the rejection behavior.
4. No regression in existing capabilities tests (`nucleus/nucleus-compiler/tests/capabilities.rs` and siblings).
5. `just check + just clippy + just test + just test-release + just e2e` all green.

## Honest scope

- This is the SCHEMA-side work that must land BEFORE TASK-0044.02 can ship its capabilities.toml. Splitting it out makes TASK-0044.02 unblocked-and-actionable rather than mid-cycle-discovering-a-schema-gap.
- If the schema validator turns out to NOT hard-code the notify list (e.g. accepts any string), the precursor is trivial / docs-only. Verify before claiming substantive work.
- Don't add 'event'-equivalence to poll. Poll is a busy-wait primitive; it does NOT provide the event-readiness semantics mp-tcp-event needs.
