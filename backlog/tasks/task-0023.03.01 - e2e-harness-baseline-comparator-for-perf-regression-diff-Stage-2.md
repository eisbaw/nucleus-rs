## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0023.03 Stage 1 (cycle-54) landed `--emit-timings PATH`, persisting per-cell wall-clock timings as JSON in planned (deterministic) order. The schema is documented in src/main.rs (cell_result_to_json + render_timings_json) and verified by 6 unit tests.

Stage 2 adds the baseline comparator. Acceptance:

- [ ] `--baseline PATH --emit-timings DEST`: load PATH, run normally writing to DEST, then print a delta table on stderr.
- [ ] Delta table groups by cell-key (example, schedule, backend) and reports `total_ms_baseline -> total_ms_current (Δ pct)`, sorted by largest regression first.
- [ ] Pretty output uses ANSI red for slower (>0 pct), green for faster (<0 pct). Plain-text fallback when stderr is not a TTY.
- [ ] Missing-cell on either side is reported as "(new)" / "(removed)" rather than crashing — matrix evolves between runs.
- [ ] Baseline JSON parse failure is LOUD with line/column where possible (hand-rolled minimal JSON parser, or use a tiny crate if dep budget allows — Stage 1 deliberately avoided serde_json).
- [ ] Unit test: round-trip a synth Vec<CellResult>, mutate one cell's run_ms, assert the delta table flags exactly that cell.

Out of scope: per-cell perf_threshold_pct gating (that's Stage 3). Determinism-mode --emit-timings (file separately if Mark wants it).

Implementation hook: the existing `args.emit_timings: Option<PathBuf>` and `write_timings_json` are the foundation. Add `args.baseline: Option<PathBuf>` and a `compare_against_baseline(baseline, results)` fn called before/after `write_timings_json`.

## Implementation Notes

cycle-55 implementer notes (Stage 2):

File changes (all in nucleus/e2e/src/main.rs):
- Args struct: added `baseline: Option<PathBuf>` (line ~360) with default + parser support for both `--baseline PATH` and `--baseline=PATH`. PATH existence is validated at parse time -- a typoed/missing baseline fails LOUD up front rather than silently no-op'ing after the matrix has paid its cost.
- New section "Baseline comparator (TASK-0023.03 Stage 2)" between write_timings_json and execute_cells_parallel (lines ~2884-3475):
  * `BaselineCell` struct -- subset of the emitter schema the comparator needs (identity triple + total_ms).
  * `BaselineParseError` -- carries byte offset + snippet for loud diagnostics.
  * `parse_baseline_json` + `JsonCursor` -- hand-rolled minimal JSON reader matching exactly the shape `render_timings_json` emits. Unknown keys are silently skipped (forward-compatible with Stage 3 schema additions); structural errors carry byte offset + 40-byte snippet. NO new deps (matches Stage 1's no-serde_json constraint).
  * `DeltaRow` + `compute_delta_rows` -- joins current results to baseline on (example,schedule,backend); sorts by largest regression first; new/removed cells sink to bottom (tier 1=removed, 2=new). Div-by-zero corner: baseline_ms=0 with non-zero current renders as `(baseline=0 ms; Δ undefined)`.
  * `render_delta_table` -- multi-line text output, ANSI-coloured iff caller passes color=true (red for >0%, green for <0%, dim for sentinels).
  * `compare_against_baseline` -- driver: read+parse+compute+render, ANSI iff `std::io::stderr().is_terminal()`, write to STDERR. STDERR specifically so it does NOT corrupt `--format=junit` XML on STDOUT.
- Call site (line ~3360): added the comparator after `write_timings_json` so a single invocation can both emit fresh timings and diff against an older baseline.
- `--check-determinism` mode: added a WARNING when --baseline is set (out of scope for Stage 2, mirrors the --emit-timings warning).
- Help text updated.
- 7 new unit tests (passing): parse round-trip, loud-fail on malformed input, loud-fail on missing `cells` key, regression-largest-first ordering, new/removed handling, ANSI vs plain rendering, end-to-end compare flow.

Verification gate:
- `just e2e`: 88/70/0/18, identical to pre-flag (--baseline opt-in only).
- `just test`: 64/0/0 e2e unit tests (was 57; +7 new), all other crates unchanged.
- `just clippy`: clean (needless_lifetimes + unnecessary_sort_by fixed).
- Integration runs:
  * `--emit-timings /tmp/c55-base.json` then `--baseline /tmp/c55-base.json --emit-timings /tmp/c55-now.json` -- prints delta table to STDERR with all rows in the ±5% noise range (deltas seen up to -26.3% caused by build-cache warm-up between the two invocations; that's expected variance, not a bug).
  * `--baseline /tmp/c55-bad.json` with a truncated JSON file -- exits 1 with: `--baseline: JSON parse error at byte offset 26: expected `,` or `}` in cell object (near `s": [{"example":"x"`) in `/tmp/c55-bad.json``.
  * `--format=junit --baseline ...` -- STDOUT carries clean JUnit XML; STDERR carries the delta table. The split-stream contract holds.

Honest limits:
- The hand-rolled JSON reader accepts integers only for `total_ms` (negative or floating-point would loud-fail). This matches what the emitter produces and what the comparator reads, so it's a feature, not a gap. A Stage-3 schema that adds `perf_threshold_pct` as a float would need a float branch added to `parse_u64`/skip_value.
- Build-cache warm-up between two full-matrix runs produces deltas up to ~25%. The comparator surfaces these honestly; perf-threshold gating (Stage 3) is what makes them actionable.
- `compute_delta_rows` uses HashMap<(String, String, String), &...> for the join. For the current matrix size (88 cells) the allocation cost is negligible; a future ten-thousand-cell matrix would want a string-interned key.
