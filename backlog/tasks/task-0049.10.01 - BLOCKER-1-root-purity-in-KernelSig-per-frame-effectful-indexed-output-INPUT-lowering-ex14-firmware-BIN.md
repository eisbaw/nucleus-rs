## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Slice A of TASK-0049.10 (per the parent's suggested A/B/C/D order). ROOT FIX for BLOCKER 1: the 'effectful' kernel marker is lost before the codegen contract, so an effectful indexed-output zero-input kernel (fe_capture/rf_receive: () -> i32[SAMPLES_PER_FRAME] effectful, fired as mic_in[frame] <-- fe_capture()) is structurally indistinguishable from a pure indexed compute and lowers in the embedded backend's render_fire to the zero-returning extracted stub kernels::fe_capture(). Result: firmware mic_in/bt_in are all zeros => cannot match the REAL reference.bin.

TRACTABILITY (orchestrator-verified 2026-06-03): ResolvedKernel already carries purity: Purity (algo/ir.rs:134). The gap is sidecar::KernelSig (the codegen contract the embedded backend reads via NameSidecar.kernel_sigs) copies ONLY params+ret, NOT purity (sidecar.rs:391, whose own docstring flags this exact omission as the DIVERGENCE HAZARD). So slice A is BOUNDED: (1) add purity (recommend deriving serde on Purity and storing purity: Purity, which directly discharges the DIVERGENCE HAZARD; is_effectful: bool is an acceptable alternative) to KernelSig and populate it in build_sidecar from ResolvedKernel.purity; (2) in embedded render_fire (render.rs ~502 'Indexed OUTPUT (pure compute)' arm), add an ADDITIVE sub-branch: an EFFECTFUL kernel with an indexed output AND no inputs lowers to a per-frame shim region-read into the indexed slice (e.g. mic_in[frame], sized by the row not the whole array) instead of the kernels::callee() stub call.

SCOPE: INPUT only. fe_emit/rf_transmit (effectful, output=None) per-frame OUTPUT drain is slice B (TASK-0049.10.B). Per-worker input partition + multi-output capture .resc is slice C. renode-multimcu recipe resolution + byte-exact gate is slice D. Do NOT claim byte-exact in slice A (not achievable until C+D land).

REGRESSION GUARD (load-bearing): the existing STRUCTURAL classification in render_fire (output None => save; whole-array output + empty inputs => load; indexed output => pure stub call) backs 7 M6 cells + M10 ex1/5/9 + 02-split-add. The purity-aware path MUST be purely ADDITIVE — it only adds a new arm for the indexed-output + effectful + no-inputs shape, which NO shipped cell exercises. e2e MUST stay 427/364/0/63/0 byte-for-byte.
