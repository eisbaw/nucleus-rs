## Background

Jacobi iteration: out[i][j] = 0.25 * (in[i-1][j] + in[i+1][j] + in[i][j-1] + in[i][j+1]), applied REPEATEDLY until max(abs(out - in)) < tolerance.

Filed under TASK-0341 (showcase example expansion).

## Why this example

The 5-point stencil pattern is already well-covered by 05-stencil and 06-separable-filter. What's NEW here is the ITERATIVE-UNTIL-CONVERGENCE structure:

- Run the stencil pass.
- Compute max-abs-difference between input and output (a REDUCTION).
- If diff > tolerance, swap input/output and repeat.
- If diff <= tolerance, halt.

This is a HIGH-LEVERAGE gap probe: it surfaces whether the current Event::Loop shape handles 'loop with data-dependent termination', or only fixed-iteration loops. Every iterative numerical method needs this — CG, GMRES, eigensolvers, multigrid, etc. If the DSL can't express it cleanly, knowing that NOW (before M6 ships) is more valuable than discovering it during a later milestone.

## Honest gotchas (and why bit-identical is achievable)

- FP convergence is order-dependent in general → cross-backend differential would NOT be bit-identical with naive parallel reduction.
- MITIGATION: use FIXED-POINT arithmetic (e.g. i32 scaled by 2^16, treat tolerance as integer threshold). All backends will produce bit-identical output regardless of summation order.
- This is a deliberate constraint to KEEP THE EXAMPLE TESTABLE — production-grade Jacobi would use FP and accept reduction-order non-determinism, but for the showcase matrix this trade is worth it.
- Alternative: pick the test input + tolerance + max-iter to produce IDENTICAL output across all reduction orders. Harder to engineer; only works for very small problem sizes.

## What this exercises in the compiler that no existing example does

- 'Loop until condition' control flow (vs current Event::Loop's fixed-range structure).
- Reduction CONSUMED in the loop test, not just produced as output.
- Pointer/buffer swap between iterations (the 'double-buffering' pattern).
- Possible interaction with reuse_inference if iteration N reuses iteration N-1's output buffer.

EXAMPLE NUMBER: 16-jacobi.

DIMENSIONS:
- H = W = 8 (8x8 grid, modest, observable)
- ITERS = 4 (fixed; 5 generations total at ITERS+1 indices)
- seed: 64 i32 = 256 B input
- field: 5 generations × 64 i32 = 1280 B internal state (single-assignment)
- result: 64 i32 = 256 B output

SINGLE-ASSIGNMENT PATTERN (from 11-game-of-life precedent):
- `data seed[H][W]` — loaded once via load_input
- `data field[ITERS+1][H][W]` — single Dataflow stmt covers ALL iterations + seed staging
- `data result[H][W]` — extracted from field[ITERS] via ident copy loop
- Kernel `jacobi5_or_seed(n, s, e, w, seed_yx, t) -> i32 pure`:
  - t==0: return seed_yx
  - t>=1: return (n + s + e + w) / 4 (integer division, deterministic)
- Boundary handling: only interior (y in 1..H-1, x in 1..W-1) is written; boundary cells stay 0 (Dirichlet BC by single-assignment default, same as 05-stencil)
- Index expression `field[(t + ITERS) % (ITERS + 1)][y][x]` — at t=0, wraps to field[ITERS] (uninitialized 0); at t>=1, refers to field[t-1] (just-written previous generation)

KERNELS:
- jacobi5_or_seed: i32 input/output, integer division by 4 (deterministic; loses precision vs FP average but bit-deterministic across schedules/backends)
- ident: identity copy for staging field[ITERS] -> result
- load_input/save_output: same Vec<i32> bulk-IO pattern

INPUT PATTERN:
- seed[y][x] = ((y * 17 + x * 13) & 0xFF) — varied across both axes, small range so 4-tap sum stays in [0, 1020], no wraparound after / 4
- After 4 Jacobi iterations with 0-boundary, interior values diffuse toward 0 (low-pass filter); reference computes exactly the same sequence so bit-identical match
