## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Architect P3.1 (cycle-243, TASK-0422 review). The inv(2) production gate is wired at driver/src/main.rs:785 (validate_event_lists(&per_worker) before dispatch_backend). The cycle proves: (a) the validator LOGIC rejects unmatched pairs (unit bite test task0422_gate_wired_reject.rs), and (b) it does not reject any valid corpus program (e2e 385/328 green). But NO test exercises cmd_build's actual CALL of the validator. Because no valid .nuc source produces an inv(2) violation, the reject arm of the driver path is undriveable from real input — so if a future refactor deleted line 785, every unit test would still pass AND e2e would stay green (e2e is positive-direction only: it proves the gate does not reject valid input, never that the gate is still present/invoked). This is a latent silent-removal risk for a fail-loud tripwire. SCOPE: add a cmd_build-level (or near-driver) test that injects an inv(2)-violating EventList via a test seam and asserts the driver path returns the validation Err. The seam does not exist today; designing the least-invasive one (e.g. a #[cfg(test)] hook, or factoring the post-projection gate sequence into a testable fn taking per_worker) is the task. Keep it honest: do NOT fake an end-to-end .nuc reject (none exists). LOW priority — the structural argument + e2e green make the gate correct TODAY; this guards against future regression. Pointer: driver/src/main.rs cmd_build ~736-793; nucleus-compiler/src/event_validate.rs validate_event_lists.
