## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Architect cycle-201 P3.2: nuc-nucleus/examples/14-hearing-aid/kernels.rs::save_chunk opens output with OpenOptions::new().create(true).write(true) but NOT truncate(true). If a prior run wrote a longer file at the same NUC_OUTPUT_PATH, residual bytes past 2*BUFFER_BYTES survive. Not observable in the e2e harness (fresh per-run scratch dirs per memory project-e2e-harness-scratch-lifecycle), but is a robustness nit.

Fix options:
(a) Add .truncate(true) — but then the order between save_spk and save_bt_out matters (the second seek+write would truncate everything before reseeking). Would need explicit pre-write size-set OR the host-elected save_* would need to truncate to 2*BUFFER_BYTES before either save runs.
(b) Document the assumption that NUC_OUTPUT_PATH must not pre-exist or must be the e2e harness scratch path. Less invasive.

Priority: LOW. Filed as cycle-201 fold-back.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Cycle-212b plan (orchestrator in-thread; trivial fix).

CHOSEN: option (a) done correctly via set_len, NOT truncate(true). Rationale:
- truncate(true) is ORDER-DEPENDENT and WRONG here: the 2nd save_chunk open would wipe the 1st chunk before reseeking.
- f.set_len((2*BUFFER_BYTES) as u64) right after open is ORDER-INDEPENDENT: both chunks live within [0, 2*BUFFER_BYTES), so set_len drops only residual bytes PAST 2*BUFFER_BYTES (the robustness bug), preserves the other chunk, and extends a short prior file with zeros.
- BYTE-IDENTITY preserved: on a fresh e2e scratch file (0 bytes), set_len->2*BUFFER_BYTES zeros then both chunks fully overwrite [0,2*BUFFER_BYTES); final bytes identical to today's no-set_len behavior. So e2e 308/246/0/62/0 unchanged.

Steps:
1. Add f.set_len after open, before seek; update the now-inaccurate "let the OS file-size logic do the rest" comment to describe the set_len + cite TASK-0054.02.
2. Gate: build/clippy/test/test-release/e2e via qa-test-runner; baseline 308/246/0/62/0 must hold (example-14 cell bit-identical = the regression proof).
3. Prove-it-bites: standalone manual check (replicate open/set_len/seek/write against a pre-populated 3*BUFFER_BYTES file; assert final == exactly 2*BUFFER_BYTES, both chunks correct, residual gone). Cannot be a nucleus unit test (kernels.rs is copied into the emitted project, not include_str!'d into the nucleus test suite) nor an e2e test (fresh scratch dirs). Document this honestly.
4. mped-architect read-only review of the set_len-vs-truncate reasoning + comment accuracy + byte-identity argument.
