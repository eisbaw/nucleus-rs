## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0461 bounded the host accept ONLY on the shared backend_common::tcp_plan::worker_program path (mp-tcp-bufsync + mp-tcp-poll), via wire::accept_with_deadline + handshake_deadline_ms (NUC_HANDSHAKE_DEADLINE_MS, 30s default, fail-loud). SILENT SIBLING: the async event backends emit their OWN host setup from SEPARATE Plan implementations — mp-tcp-event/src/plan.rs:113/119 and mp-uds-event/src/plan.rs:156/162 — each with a bare unbounded listener.accept() (BEFORE the std->mio nonblocking conversion). Same 10.5h-at-0%-CPU connect/accept-phase hang class as TASK-0461. Their wire-level READS are already mio-nonblocking + deadline-bounded (event reactor), so the residual unbounded call is the host ACCEPT only. FIX: route those two plan.rs accept sites through the same wire::accept_with_deadline helper (already shipped in mp-tcp-common/src/wire_runtime.rs and copied verbatim into every generated project). NOT done in TASK-0461 because backends/*/src is outside that task agents ownership (tcp_plan + tests + e2e harness only). Grep-witness recorded: grep -n "listener.*accept()" nucleus/backends/mp-tcp-event/src/plan.rs nucleus/backends/mp-uds-event/src/plan.rs. Also: mp-tcp-event/src/multi_worker.rs + mp-uds-event/src/multi_worker.rs carry reference-impl accept() copies (test fixtures) — audit those too.

GOTCHAS: (1) tuple-vs-stream return — helper returns the stream DIRECTLY, so the (x,_)= destructure + .unwrap_or_else were DROPPED at all 4 sites; the panic is internal to the helper.
