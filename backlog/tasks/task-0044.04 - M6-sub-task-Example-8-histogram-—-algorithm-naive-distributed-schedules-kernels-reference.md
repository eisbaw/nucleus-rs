## Goal

Land example 8 — histogram — per PRD §9 row 8: 'Reduction with shared output array'. Distinct from example 3 (reduction-to-scalar) by reducing to an N-bin array via index-dependent accumulation.

## What this stresses (per PRD §9)

- Read-side: streaming over an input array.
- Write-side: SHARED OUTPUT ARRAY where each input value indexes into a different bin (non-trivial fan-in pattern).
- Schedules: naive (single worker) + distributed (partition the input + per-worker partial-histogram + final reduce). The DISTRIBUTED schedule is the load-bearing test of cross-worker partial-result combination on an ARRAY output.

## Closest template

`nucleus/examples/03-reduction/` — the existing reduction example. Reuse:
- Algorithm sublanguage pattern: declare `data input : T[N]`, `data output : T[BINS]`, a kernel that takes a slice, writes a bin index.
- Schedule pattern: `distributed` schedules partition the input dimension across workers; per-worker partial output is combined.

The diff is the OUTPUT SHAPE: 03-reduction has scalar output (one f32), 08-histogram has array output (BINS-element u32 array). Partial-histogram combination is element-wise add across worker-local arrays.

## Deliverables

2. `naive.sched.nuc` schedule lowers + emits + runs bit-identical against `reference.bin` on pthreads-sync AND mp-tcp-bufsync.
3. `distributed.sched.nuc` schedule lowers + emits + runs bit-identical against reference.bin on at least one tier-1 backend that supports partition-then-reduce (pthreads-sync via TASK-0258 partition_rows, or pthreads-async via the M5 distributed machinery).
4. `kernels.rs` is pure Rust, deterministic, no floating-point non-associativity surprises (use integer bins; document any f32 use).
5. Reference impl in `reference/` is INDEPENDENT — not derived from kernels.rs. Both produce identical reference.bin (the differential oracle).
6. README documents: required schedules, which backends support each, what algorithmic pattern this stresses, honest limitations.
7. e2e-matrix.toml has entries for each (schedule, backend) cell with the right [[required]] / [[skip]] markers; reasons reference the right TASK IDs (e.g. TASK-0042 capability mismatch for async-only backends if applicable).

## Honest scope

- Histogram has a SUBTLE DETERMINISM HAZARD: if the bin-increment kernel sees a race (multiple workers updating the same bin), the output is non-deterministic. The whole point of the SCHEDULE is to AVOID this — per-worker partial histograms are combined by a single reducer. Make sure neither the algorithm nor any schedule expresses an unguarded shared-bin write.
- BINS should be small enough that partial-histogram-per-worker is cheap (e.g. 256 bins for u8 input). Document the BINS / N tradeoff.
- The distributed schedule's partial-combine is the cross-worker fan-in pattern; this exercises a different combinator shape than 03-reduction (per-bin sum across workers, not scalar accumulator chain).
