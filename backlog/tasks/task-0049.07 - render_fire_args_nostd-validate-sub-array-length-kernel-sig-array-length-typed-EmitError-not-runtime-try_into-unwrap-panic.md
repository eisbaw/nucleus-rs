TASK-0049.06 review (architect P2.1). backend-common render/fire.rs render_fire_args_nostd emits slice[start..start+sub_len].try_into().unwrap() for an array-typed pure-kernel sub-array arg. The target [T; N] length N is inferred from the kernel signature (sidecar.kernel_sigs) while sub_len derives from the DATA trailing dims (sidecar.data_types) — two DIFFERENT sidecar tables, NOT cross-validated anywhere in contract/link/type checking (contract.rs only matches scalar sigs; aggregate params get a non-fatal TypeMismatch warning). If a shape-mismatched-but-otherwise-legal schedule is placed, the slice length (a RUNTIME range) != N, so the try_into to [T;N] returns Err and unwrap PANICS on-device at runtime — cargo check does NOT catch it (panic-not-diagnostic recurring class; strictly worse than the tier-1 to_vec path where a length mismatch is a compile-time E0308). For example-14 the lengths genuinely match (both 16) so this is LATENT, not active. FIX: at emit time in render_fire_args_with (FixedArray arm, ~fire.rs:285-296), compare sub_len against the kernel-sig param array length and return a typed EmitError on mismatch (and/or a contract/link-level aggregate-shape check). The docstring there was corrected in the TASK-0049.06 fold-back to state the invariant is currently UNCHECKED and point here.
