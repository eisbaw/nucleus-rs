## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Forward-carried gap from TASK-0048.02. The TASK-0048.02 real-input mechanism (B, Renode-injected axiSram region) relies on an ASSUMPTION: input.bin is the concatenation of the effectful-load arrays IN EventList load order, so the firmware's Usart1Shim cursor (advancing by each load's byte length) reads the right slice per load. For ex1 this is exact (a=words[0..N] loaded first, b=words[N..2N] loaded second). ex5 (single load load_image -> img_in) and ex9 (single load load_input -> seeds) are single-load so the cursor trivially starts at 0 and consumes the whole region — but this MUST be verified per example, not assumed, when TASK-0048.03 generates+runs their firmware. If any future M10 example has multiple loads whose input.bin layout does NOT match EventList order, the cursor reads the wrong slice and the reference.bin cmp will (correctly) fail. AC: (1) when TASK-0048.03 wires ex5/ex9, confirm each example's input.bin byte layout matches the EventList load order before trusting the cmp; (2) if a mismatch is possible, replace the implicit cursor with an explicit per-load offset derived from a stable source (sidecar/Event metadata), not kernel-body parsing.
