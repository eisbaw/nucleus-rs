## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Architect P1 on TASK-0049.05 (commit e8ae76d). The multi-MCU BIN MultiMcuShim lowers EVERY Event::Sync to a no-op irq_barrier (render.rs ~:369). This is value-correct ONLY when the barrier ordering is already subsumed by a blocking Push/Wait data edge — true and VERIFIED for 02-split-add (its tag0/1/2 Syncs are control-only but data-edge-redundant; byte-exact diff holds). But the no-op is UNCONDITIONAL: a schedule whose correctness needs a standalone control barrier with NO co-located data edge would be SILENTLY miscompiled. The compiler can distinguish the two cases (happens-before subsumption analysis). Add a typed EmitError on the multi-MCU BIN path that REJECTS a control-only Sync whose ordering is not provably carried by data edges (matching the repo fail-loud-tripwire discipline; cf. TransferInjectError::CumulativeWholeArrayFallback precedent). NB a naive "reject any Sync" is WRONG — it would reject the value-correct 02-split-add; the guard must detect non-redundant barriers. Mitigation today: the tier-3 acceptance is always the byte-exact reference.bin diff, which fails loud if the no-op breaks a schedule — so the risk is bounded to trusting BIN output without that diff.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
ORCHESTRATOR DESIGN-SCOPING (cycle, no code landed): empirically grounded the subsumption analysis on 02-split-add/split (the one case that MUST NOT be rejected — its no-op irq_barriers are byte-exact). Generated the multi-MCU emit (nucleus build --backend embedded-pattern --shim stm32h7) and read the per-worker run() bodies:

  host: push a(seq0) -> push b(seq1) -> barrier0 -> [loop: barrier1] -> barrier2 -> recv c(seq2) -> save
  w0:   barrier0 -> recv a(seq0) -> recv b(seq1) -> [loop: barrier1, compute] -> push c(seq2)
  data edges (Push->Wait by seq): host.push_a->w0.recv_a; host.push_b->w0.recv_b; w0.push_c->host.recv_c

KEY FINDING — the OBVIOUS formulation is UNSOUND-for-purpose (false-rejects 02-split-add): "barrier S(participants P) is subsumed iff for every ordered pair (a,b) in P, pred_S(a) reaches succ_S(b) in the (program-order + Push->Wait) graph." Test on Sync tag 0 {host,w0}: pred on host = push_b(seq1), succ on w0 = recv_a(seq0). recv_a is reachable only from push_a, which precedes push_b in program order => NOT reachable => this formulation REJECTS Sync tag 0. But 02-split-add is value-correct with the no-op. So the barrier-position-reachability check FALSE-REJECTS the must-pass case and is wrong.

WHY: the barrier provides ALL-TO-ALL ordering, but only a SUBSET of that ordering is needed for correctness. The no-op is safe iff every REAL cross-worker dependency the barrier was incidentally covering (push_a->recv_a, push_b->recv_b, push_c->recv_c) is ALSO carried by a data edge — which it is. A SOUND guard therefore needs a cross-worker DATA-DEPENDENCY model (which RAW/WAR/WAW edges exist across workers, and whether each is independently carried by a blocking Push/Wait), NOT a check that the barriers full ordering is reproduced.

DEEPER OBSERVATION: in the current multi-MCU BIN model there is NO shared memory and the ONLY effect is the single output workers USART1 capture. All cross-worker sharing rides blocking link_recv. So a control-only barrier is essentially ALWAYS redundant here, and a genuinely non-redundant standalone barrier may not be constructible from any sound .nuc schedule today (reachability class (b), IR-constructible only — cf. the TASK-0281/0365 cross-partition-reducer precedent). The guard would need a synthetic non-redundant-barrier fixture to prove-it-bites; there is no in-tree positive case.

RECLASSIFICATION: this is NOT a tail-end "add a guard" cycle. It needs a DESIGN SLICE: (1) define the cross-worker dependency model + the sound subsumption predicate (and whether the safe direction is over-rejection); (2) decide if a non-redundant barrier is even reachable from a sound schedule (if class-(b)-only, the guard mirrors TASK-0281: a conservative tripwire whose positive arm is synthetic-only); (3) build a synthetic prove-it-bites fixture at the multi-MCU emit layer. Until then the documented mitigation stands: the tier-3 acceptance is the byte-exact reference.bin diff, which fails loud if a no-op breaks a SHIPPED schedule. The risk is bounded to trusting BIN output WITHOUT that diff. Natural home for the check: TransportPlan::build (multimcu.rs) which already has the full per_worker view + emits typed EmitError.
