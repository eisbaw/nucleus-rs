# Example 10 — wavefront (2D accumulated-cost matrix)

## What this stresses

PRD §9 row 10: "Diagonal dependency, ordering, no SIMD."

The accumulated-cost recurrence
```
out[i][j] = in[i][j] + min(out[i-1][j], out[i][j-1], out[i-1][j-1])
```
is a 2D wavefront: each interior cell depends on its NW, N, and W
neighbours. The natural sequential evaluation is row-major (each
cell reads cells already written); the natural parallel evaluation
is anti-diagonal (cells on the same diagonal `i+j == k` are mutually
independent, diagonals execute in increasing k). This is the canonical
shape behind Smith-Waterman alignment, dynamic time warping, and
Cocke-Younger-Kasami parsing.

## What this DOES demonstrate

- The algorithm/schedule split survives a 2D recurrence at the
  KERNEL level: one pure kernel `wavefront(in)` produces the
  accumulated-cost matrix, the algorithm declares only the dataflow
  edge `in_cost -> wavefront -> out_cost`.
- The cross-backend differential: 7 tier-1 backends emit bit-identical
  output against the reference oracle (whose control structure is
  deliberately different — see `reference/` directory).

## What this does NOT demonstrate (honest limitations)

- **The wavefront recurrence at the algorithm level.** Nuc v2's
  no-conditionals (PRD §6.2.4) + single-assignment-per-data-symbol
  (PRD §6.2.1) rules forbid the in-array carried recurrence
  `out[i][j] <-- step(out[i-1][j], ...)` at the algorithm level:
  the boundary at i=0/j=0 needs a conditional that v2 cannot
  express, and splitting boundary base-case + recursive case is a
  DoubleAssignment on the `out` data symbol. Same limit hit by
  04-prefix-sum (TASK-0179). The recurrence lives in the Rust
  kernel; the algorithm sees only the wrapping dataflow edge.
- **The diagonal-parallel schedule.** With only one fire site per
  algorithm run (one `wavefront` call), there is no decomposition
  axis for the schedule sublanguage to attach a `partition=` or
  `pipeline=` directive to. Expressing the anti-diagonal traversal
  at the schedule level would require either (a) grammar extensions
  for in-array carries at the algorithm level, or (b) a multi-pass
  diagonal-indexed encoding that requires loop bounds dependent on
  loop variables (also blocked by the const-loop-bound rule). Filed
  as **TASK-0044.05.01** for future grammar work.

## Numeric choice

`i32` with `wrapping_add` and `min`. PRD §10.1: integer arithmetic
is bit-deterministic across schedules and backends; reorderable
floating-point min/sum is not. `wrapping_add` makes overflow
behaviour explicit. The committed fixture (see "Input distribution"
below) keeps the accumulated cost in-range — wrap is impossible for
the shipped fixture.

## Input / output format

`input.bin` and `reference.bin` are H*W = 16*16 = 256 i32
little-endian words each, row-major (row i occupies words
[i*W .. (i+1)*W)). Total 1024 bytes per file.

### Input distribution

```
in_cost[i][j] = ((i * 31 + j * 17 + 5) & 0x3F) + 1
```

Range [1, 64]. Maximum possible accumulated value bounded by
H * W * 64 = 16384, far inside i32 range. Generated by
`reference/` in `--gen-input` mode (no python step).

## Schedules

- `naive.sched.nuc` — single `host` worker, sequential. Every kernel
  placed on host, no loop transforms, no transfers. The shipped
  schedule.

The anti-diagonal parallel schedule is filed as a future-grammar
follow-up (TASK-0044.05.01) — see the "honest limitations" section
above for why it is not currently expressible in v2.

## Regenerate fixtures

```
cargo run --release \
  --manifest-path nuc-nucleus/examples/10-wavefront/reference/Cargo.toml -- \
  --gen-input nuc-nucleus/examples/10-wavefront/input.bin

cargo run --release \
  --manifest-path nuc-nucleus/examples/10-wavefront/reference/Cargo.toml -- \
  --in  nuc-nucleus/examples/10-wavefront/input.bin \
  --out nuc-nucleus/examples/10-wavefront/reference.bin
```

## Reference impl independence

`reference/` is a standalone Rust crate (no nucleus deps, std-only).
It computes the same accumulated-cost matrix with a different
control structure: an explicit diagonal sweep (k = 0..H+W-1; cells
on diagonal k; ordered i within diagonal) instead of the kernel's
row-major sweep. Both orders produce identical output because the
recurrence depends only on cells from EARLIER diagonals, and `min` /
`wrapping_add` are deterministic and order-independent on fixed
operands. Conforms to `docs/reference-impl-policy.md` §2 (no shared
code with kernels.rs) + §5 (integer arithmetic only, no floats).

## Contract-check limitation

The contract pass reports `TypeMismatch` for the aggregate-typed
`load_input` / `save_output` / `wavefront` kernels (declared
`i32[H][W]`, Rust uses `Vec<i32>`). Known TASK-0012 limitation;
identical to examples 01..07. Emit proceeds with a warning.
