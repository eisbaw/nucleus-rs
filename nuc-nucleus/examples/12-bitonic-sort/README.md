# Example 12 — bitonic sort

## What this stresses

PRD §9 row 12: "Static communication pattern, fits SDF."

The bitonic-sort network has a static compare-exchange pattern
determined entirely by input size: log2(N) outer stages × variable
inner stages, with per-element pair assignment computed from the
element index and stage bit-pattern. Despite being a SORT (each
comparator's output depends on its input values), the COMMUNICATION
pattern is fully scheduled at compile time — making it a clean fit
for the synchronous-dataflow (SDF) model.

For N=64 (the shipped fixture), there are 6 outer stages and 21
inner stages total.

## What this DOES demonstrate

- The algorithm/schedule split survives a static-network sort at
  the KERNEL level: one pure kernel `bitonic_sort(input)` produces
  the sorted output; the algorithm declares only the dataflow edge
  `input -> bitonic_sort -> output`.
- The cross-backend differential: 7 tier-1 backends emit bit-identical
  output against an independent reference oracle (`std::sort_unstable`
  — a radically different algorithm vs the bitonic network).

## What this does NOT demonstrate (honest limitations)

- **The stage-by-stage compare-exchange network at the algorithm
  level.** Nuc v2's no-conditionals (PRD §6.2.4) + single-assignment-
  per-data-symbol (PRD §6.2.1) + const-loop-bound rules forbid the
  natural stage-decomposed encoding:
  - Each stage uses a different bit-pattern of `i` to select compare-
    exchange pairs (`l = i ^ j`). Encoding this at the algorithm
    level would need either (a) ~21 hardcoded stage blocks for N=64
    (feasible but tedious / brittle), or (b) loop bounds dependent
    on a loop variable (rejected by const-loop-bound rule).
  - The compare-exchange writes BOTH elements of the pair (`output[a]
    = min`, `output[b] = max`). v2's single-assignment-per-data-
    symbol rule treats `output` as one symbol; the kernel-level
    accumulator trick (see 04-prefix-sum) works for sum-shaped
    reductions, not for permutations.

  Same fundamental limit hit by 04-prefix-sum (TASK-0179) and
  10-wavefront (TASK-0044.05.01). The network lives in the Rust
  kernel; the algorithm sees only the wrapping dataflow edge.

- **The stage-parallel schedule.** With only one fire site per
  algorithm run (one `bitonic_sort` call), there is no
  decomposition axis for the schedule sublanguage to attach a
  `partition=` or `pipeline=` directive to. Expressing the
  intra-stage parallelism (N/2 compare-exchange comparators run
  concurrently within a stage; barrier between stages) at the
  schedule level would require either grammar extensions for
  stage-by-stage algorithm decomposition or a multi-pass
  algorithm-level encoding that's currently blocked. Filed as
  **TASK-0044.06.01** for future grammar work.

## Numeric / value choice

`i32` values, distinct (no equal-key stability question). PRD §10.1:
integer comparison is bit-deterministic by language definition.
Distinct values ensure the `sort_unstable` reference impl and the
deterministic bitonic kernel both produce the unique sorted
permutation.

## Input / output format

`input.bin` and `reference.bin` are N = 64 i32 little-endian words
each. Total 256 bytes per file.

### Input distribution

```
input[i] = ((i * 53 + 13) mod N) * 7 + 100
```

53 is coprime to 64 (53 is odd), so `i * 53 mod 64` is a permutation
of [0, 64). Therefore the input is a permutation of
{ k * 7 + 100 : 0 ≤ k < 64 } = {100, 107, 114, ..., 541}. Distinct,
well-separated, well inside i32 range. The sorted output is the
same set in increasing order. Generated by `reference/` in
`--gen-input` mode (no python step).

## Schedules

- `naive.sched.nuc` — single `host` worker, sequential. Every kernel
  placed on host, no loop transforms, no transfers. The shipped
  schedule.

The stage-parallel schedule is filed as a future-grammar follow-up
(TASK-0044.06.01) — see the "honest limitations" section above.

## Regenerate fixtures

```
cargo run --release \
  --manifest-path nuc-nucleus/examples/12-bitonic-sort/reference/Cargo.toml -- \
  --gen-input nuc-nucleus/examples/12-bitonic-sort/input.bin

cargo run --release \
  --manifest-path nuc-nucleus/examples/12-bitonic-sort/reference/Cargo.toml -- \
  --in  nuc-nucleus/examples/12-bitonic-sort/input.bin \
  --out nuc-nucleus/examples/12-bitonic-sort/reference.bin
```

## Reference impl independence

`reference/` is a standalone Rust crate (no nucleus deps, std-only).
It sorts using std's `sort_unstable` (pdqsort variant) — a radically
different algorithm from the bitonic compare-exchange network in
`kernels.rs` (quicksort/pdqsort is comparison-based and value-driven;
bitonic is static-network and structure-driven). For distinct input
values both algorithms produce the unique sorted permutation, so
bit-identicality is meaningful evidence of the bitonic kernel's
correctness. Conforms to `docs/reference-impl-policy.md` §2 (no
shared code with kernels.rs) + §5 (integer arithmetic only, no
floats).

## Contract-check limitation

The contract pass reports `TypeMismatch` for the aggregate-typed
`load_input` / `save_output` / `bitonic_sort` kernels (declared
`i32[N]`, Rust uses `Vec<i32>`). Known TASK-0012 limitation;
identical to examples 01..07/10. Emit proceeds with a warning.
